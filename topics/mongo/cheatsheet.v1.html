MongoDB

cheatsheet · 8.3.8 · released 2026-08-11

Scan card for the MongoDB server, shell and drivers: connection and mongosh flags, CRUD and aggregation syntax, index and explain idioms, transaction, sharding, security and search commands, plus a modern-versus-legacy table and a version timeline. Everything is correct for the 8.3 series (8.3 GA 2026-05-07, latest patch 8.3.8 on 2026-08-11); 8.0.29 remains the other supported line for self-managed clusters and 7.0 is supported until 2027-08-31. Version labels mark where a feature became stable, default or deprecated — including the 8.3 Cost-Based Ranker default, the shard-draining commands that deprecate removeShard, and the December 2025 MongoBleed patch floor.

01Connect, shell & tools

Connection string first: almost every "MongoDB is slow / flaky" ticket is a URI option, not the server.

Connect (Atlas/SRV)
mongosh "mongodb+srv://app@cluster.example.net/appdb"
Connect (self-managed)
mongosh "mongodb://h1:27017,h2:27017/appdb?replicaSet=rs0"
One-liner, no banner
mongosh --quiet --eval 'db.orders.countDocuments({s:"new"})' "$URI"
Run a script file
mongosh --file migrate.js "$URI" — load() is the legacy way
Durability + retries
?w=majority&retryWrites=true&readConcernLevel=majority — all default since 5.0
Read routing
?readPreference=secondaryPreferred&maxStalenessSeconds=90
Pool
?maxPoolSize=100&minPoolSize=5&maxIdleTimeMS=60000&maxConnecting=2
Timeout (modern)
?timeoutMS=10000 — CSOT, one budget for the whole operation incl. retries
Timeout (legacy)
socketTimeoutMS / wtimeoutMS / maxTimeMS — per-hop, easy to get wrong
Compression
?compressors=zstd,snappy — drop zlib: MongoBleed, see unit 08
Always name the app
?appName=svc-orders — shows up in logs, currentOp, Atlas profiler
Server version
db.version() · mongod --version · db.runCommand({buildInfo:1})
Feature comp. version
db.adminCommand({getParameter:1, featureCompatibilityVersion:1})
Raise FCV after upgrade
db.adminCommand({setFeatureCompatibilityVersion:"8.3", confirm:true}) — confirm required since 7.0
Start server
mongod --config /etc/mongod.conf — flags are for labs; config file for real
Dump / restore
mongodump --uri="$URI" --archive=d.gz --gzip · mongorestore --archive=d.gz --gzip --nsFrom 'old.*' --nsTo 'new.*'
Bulk load JSON/CSV
mongoimport --uri="$URI" -c orders --type=json --jsonArray --file o.json
Local throwaway cluster
docker run --rm -p 27017:27017 mongo:8.3 — single node, no replica set, so no transactions

02CRUD & query operators

Insert
db.c.insertOne(doc) · db.c.insertMany(docs, {ordered:false})
Find + project + sort
db.c.find({status:"A"}, {_id:0, name:1}).sort({createdAt:-1}).limit(20)
Count
db.c.countDocuments(q) (accurate) · db.c.estimatedDocumentCount() (metadata, no filter)
Update
db.c.updateOne(f, {$set:{a:1}, $inc:{n:1}, $currentDate:{at:true}})
Field operators
$set $unset $inc $mul $min $max $rename $setOnInsert $currentDate
Array update
$push {$each,$slice,$sort,$position} · $addToSet · $pull · $pullAll · $pop
Positional
"items.$.qty" (first match) · "items.$[].qty" (all) · "items.$[e].qty" + arrayFilters:[{"e.sku":"X"}]
Upsert
{upsert:true} with $setOnInsert for create-only fields
Pipeline update (4.2+)
db.c.updateOne(f, [{$set:{total:{$add:["$a","$b"]}}}]) — can reference other fields
Read-modify-write
db.c.findOneAndUpdate(f, u, {returnDocument:"after", upsert:true})
Delete
db.c.deleteOne(f) · db.c.deleteMany(f) · db.c.drop()
Comparison
$eq $ne $gt $gte $lt $lte $in $nin
Logical / element
$and $or $nor $not · $exists $type
Array / eval
$all $elemMatch $size · $regex $mod $expr $jsonSchema $bitsAllSet
Cross-field predicate
{$expr:{$gt:["$spent","$budget"]}} — the modern replacement for $where
Case-insensitive
{collation:{locale:"en", strength:2}} — indexable; /^x$/i is not
Cursor knobs
.hint({a:1}) · .batchSize(500) · .allowDiskUse() · .maxTimeMS(5000)
Per-op concerns
{writeConcern:{w:"majority", j:true}} · .readConcern("snapshot")
// bulkWrite: one round trip, one ordered/unordered batch
db.orders.bulkWrite([
  { insertOne:  { document: { _id: 1, sku: "AB", qty: 2 } } },
  { updateOne:  { filter: { _id: 2 }, update: { $inc: { qty: 1 } }, upsert: true } },
  { deleteMany: { filter: { status: "cancelled" } } }
], { ordered: false });   // unordered keeps going past a duplicate-key error

// 8.0: client-level bulkWrite spans MULTIPLE collections/databases in one command
await client.bulkWrite([
  { namespace: "shop.orders",  name: "insertOne", document: { sku: "AB" } },
  { namespace: "shop.audit",   name: "insertOne", document: { evt: "order" } }
], { ordered: true });

03Aggregation pipeline

Filter early, project narrow, let an index serve $match+$sort at the front — everything after the first blocking stage is CPU you pay for.

Shape stages
$match $project $set/$addFields $unset $replaceWith $unwind $sort $limit $skip $count
Grouping
$group $bucket $bucketAuto $sortByCount $facet $setWindowFields $densify $fill
Joining
$lookup $graphLookup $unionWith $documents
Output
$merge (incremental upsert into a collection) · $out (replaces it wholesale)
Accumulators
$sum $avg $min $max $push $addToSet $first $last · $topN $bottomN $firstN $lastN $maxN $minN (5.2) · $median $percentile (7.0)
Correlated join
{$lookup:{from:"i", let:{o:"$_id"}, pipeline:[{$match:{$expr:{$eq:["$oid","$$o"]}}}], as:"items"}}
Explain a pipeline
db.c.explain("executionStats").aggregate(p)
Spill to disk
automatic since 6.0 (100 MB per blocking stage); allowDiskUse:false to forbid it
New in 8.3
$createObjectId $hash $hexHash $subtype $serializeEJSON $deserializeEJSON $toArray $toObject
Array index in 8.3
{$map:{input:"$a", as:"x", arrayIndexAs:"i", in:{$concat:[{$toString:"$$i"},"$$x"]}}} (or $$IDX)
$convert in 8.3
new base arg (2/8/10/16); string ↔ array/object; binData ↔ numeric array
Deprecated
$function, $accumulator, $where (8.0) · mapReduce (5.0) — port to a pipeline
db.orders.aggregate([
  { $match: { placedAt: { $gte: ISODate("2026-01-01") }, status: "paid" } },   // index-served
  { $lookup: { from: "customers", localField: "custId", foreignField: "_id", as: "cust" } },
  { $unwind: "$cust" },
  { $group: { _id: { region: "$cust.region", m: { $dateTrunc: { date: "$placedAt", unit: "month" } } },
              revenue: { $sum: "$total" },
              p95:     { $percentile: { input: "$total", p: [0.95], method: "approximate" } },
              top3:    { $topN: { n: 3, sortBy: { total: -1 }, output: "$_id" } } } },
  { $setWindowFields: { partitionBy: "$_id.region", sortBy: { "_id.m": 1 },
      output: { rolling3: { $sum: "$revenue", window: { documents: [-2, 0] } } } } },
  { $merge: { into: "revenue_by_region", on: "_id", whenMatched: "replace" } }
], { allowDiskUse: true, hint: { status: 1, placedAt: 1 } });

04Indexes, explain & plans

ESR: Equality fields first, then Sort, then Range. One compound index in that order beats three single-field ones.

Create
db.c.createIndex({tenant:1, createdAt:-1}, {name:"tenant_recent"})
Unique / partial
{unique:true} · {partialFilterExpression:{status:"active"}} — partial beats sparse
TTL
db.c.createIndex({expiresAt:1}, {expireAfterSeconds:0}) — reaper runs every 60 s, not instantly
Change a TTL
db.runCommand({collMod:"c", index:{keyPattern:{expiresAt:1}, expireAfterSeconds:3600}})
Other types
hashed · 2dsphere · text · wildcard {"$**":1} · multikey (automatic on arrays)
Safe drop rehearsal
db.c.hideIndex("tenant_recent") (4.4) → watch → dropIndex or unhideIndex
Inspect
db.c.getIndexes() · db.c.aggregate([{$indexStats:{}}]) — accesses.ops: 0 = dead weight
Explain
db.c.find(q).explain("executionStats") · modes queryPlanner | executionStats | allPlansExecution
Read the verdict
winningPlan.stage: IXSCAN good, COLLSCAN bad, SORT = in-memory sort (32 MB cap)
Ratio to watch
totalKeysExamined ≈ totalDocsExamined ≈ nReturned; covered query = totalDocsExamined: 0
Plan cache
db.c.getPlanCache().list() · .clear() · planCacheKey in explain
8.3: plan ranking
Cost-Based Ranker is the default for eligible queries (multi-planning as backup); explain and $queryStats report CBR
Pin a plan (8.0)
db.adminCommand({setQuerySettings:{find:"c",filter:{...},$db:"appdb"}, settings:{indexHints:[{allowedIndexes:["tenant_recent"]}]}})
Legacy pin
planCacheSetFilter / index filters — superseded by query settings (they do not survive restart)
Aggregate stats
db.aggregate([{$queryStats:{}}]) (7.0) for the real workload shape
Build without downtime
index builds are online since 4.2; on big clusters still do rolling builds node by node
// Does it read only what it returns?
const e = db.orders.find({ tenant: "t1", status: "paid", total: { $gt: 100 } })
                   .sort({ createdAt: -1 }).limit(50).explain("executionStats");
e.executionStats.totalDocsExamined;   // want ~50, not 4_000_000
e.queryPlanner.winningPlan.queryPlan.stage;
// ESR index for exactly that query:
db.orders.createIndex({ tenant: 1, status: 1, createdAt: -1, total: 1 });

05Modelling, validation, time series

Model for the read you actually serve. Embed what you read together; reference what grows without bound or is written by someone else.

Hard limits
16 MB per document · 100 levels of nesting · index key ≤ 8 KB (WiredTiger)
Embed when
read together, bounded (< ~100s of entries), updated together
Reference when
unbounded growth, independent lifecycle, large and rarely read
Patterns worth naming
subset · extended reference · computed · bucket · outlier · schema-version · polymorphic (single collection)
Money
NumberDecimal("19.99") (Decimal128) — never a double
Ids
ObjectId is time-ordered (first 4 bytes = epoch seconds) — good default, leaks creation time
Validation
db.createCollection("c",{validator:{$jsonSchema:{...}}, validationLevel:"moderate", validationAction:"error"})
Add later
db.runCommand({collMod:"c", validator:{...}, validationAction:"warn"}) — start with warn
Time series (5.0+)
db.createCollection("m",{timeseries:{timeField:"ts", metaField:"tags", granularity:"minutes"}, expireAfterSeconds:2592000})
Time series notes
updates/deletes allowed since 6.0 · 2dsphere + compound indexes 6.3 · 8.0 rewrote the storage for ~2× throughput
Clustered collection (5.3)
{clusteredIndex:{key:{_id:1}, unique:true}} — docs stored in _id order, no secondary _id index
Capped collections
legacy; use a TTL index or a time series collection instead
Change streams
db.c.watch([{$match:{operationType:"update"}}], {fullDocument:"updateLookup"})
Pre/post images (6.0)
collMod: {changeStreamPreAndPostImages:{enabled:true}} then fullDocumentBeforeChange:"required"
Resume safely
persist _id (the resume token) with the side effect, restart with resumeAfter/startAfter
db.createCollection("invoices", {
  validator: { $jsonSchema: {
    bsonType: "object",
    required: ["tenant", "total", "schemaVersion"],
    properties: {
      tenant:        { bsonType: "string" },
      total:         { bsonType: "decimal", description: "Decimal128, never double" },
      schemaVersion: { bsonType: "int", minimum: 3 },
      lines:         { bsonType: "array", maxItems: 500 }   // keep arrays bounded
    },
    additionalProperties: true
  } },
  validationAction: "warn"     // flip to "error" once the logs are clean
});

06Transactions & consistency

Replica set admin
rs.initiate(cfg) · rs.status() · rs.conf() · rs.add("h3:27017") · rs.stepDown(60)
Reconfigure
cfg = rs.conf(); cfg.members[2].priority = 0; rs.reconfig(cfg)
Replication lag
rs.printSecondaryReplicationInfo() · metrics.repl.network.oplogFetcherLagSeconds (8.3)
Write concern
{w:"majority", j:true} — majority is the default since 5.0; w:1 can be rolled back
Read concern
local (default) · available (sharded, orphans) · majority · snapshot · linearizable (primary only, slow)
Read preference
primary | primaryPreferred | secondary | secondaryPreferred | nearest + tag sets
Read-your-writes on secondary
causally consistent session + readConcern:"majority" — otherwise you will read stale
Transaction (modern)
session.withTransaction(fn) — retries TransientTransactionError and UnknownTransactionCommitResult for you
Transaction (legacy)
startTransaction/commitTransaction/abortTransaction hand-rolled with no retry loop
Where they work
replica set 4.0 · sharded cluster 4.2 · $lookup on a sharded collection inside a txn since 8.0
Budget
default 60 s (transactionLifetimeLimitSeconds); keep them under ~1000 documents and one round trip of user input away
Retryable writes/reads
on by default; single-document writes only, and the write must be idempotent-by-id
Single-doc atomicity
every update to one document is atomic — the first design answer, before transactions
Cross-doc without txn
outbox / transactional-outbox with a change stream, or a state machine field + idempotent consumers
const session = client.startSession();
try {
  await session.withTransaction(async () => {
    const acc = client.db("bank").collection("accounts");
    await acc.updateOne({ _id: "A", bal: { $gte: 100 } }, { $inc: { bal: -100 } }, { session });
    await acc.updateOne({ _id: "B" }, { $inc: { bal: 100 } }, { session });
  }, { readConcern: { level: "snapshot" }, writeConcern: { w: "majority" }, readPreference: "primary" });
} finally { await session.endSession(); }
// A guard in the filter ({ bal: { $gte: 100 } }) is what makes this correct — not the transaction.

07Sharding & operations

Shard key = cardinality × even write distribution × present in the common query. Get two of three and you have a hotspot or a scatter-gather.

Enable + shard
sh.shardCollection("shop.orders", {tenant:1, _id:1}) · hashed: {_id:"hashed"}
Status
sh.status() · db.collection.getShardDistribution()
Fix a bad key
sh.refineCollectionShardKey(ns, key) (4.4, suffix only) · sh.reshardCollection(ns, key) (5.0; ~50× faster and online in 8.0)
Undo sharding (8.0)
sh.unshardCollection(ns) · move an unsharded one: sh.moveCollection(ns, "shard02")
Config shard (8.0)
db.adminCommand({transitionFromDedicatedConfigServer:1}) — config server also holds data
Back to dedicated (8.3)
startTransitionToDedicatedConfigServer → getTransitionToDedicatedConfigServerStatus → commitTransitionToDedicatedConfigServer
Remove a shard (8.3)
startShardDraining → shardDrainingStatus → commitShardRemoval (stopShardDraining aborts) — removeShard is deprecated
Balancer
sh.startBalancer() / sh.stopBalancer() · per-collection sh.disableBalancing(ns) · window via settings collection
Ranges, not chunks
autosplit removed in 6.0; ranges split/merge on demand, auto-merge since 7.0
Zones
sh.addShardToZone + sh.updateZoneKeyRange — geo/tenant pinning and data residency
What's running
db.currentOp({secs_running:{$gt:5}}) → db.killOp(opid); cluster-wide: $currentOp
Slow queries
db.setProfilingLevel(1, {slowms:100, sampleRate:0.2}) → db.system.profile; log line Slow query at >100 ms
Health
db.serverStatus() · db.hello() · mongostat / mongotop · FTDC in diagnostic.data (default 500 MB since 8.3)
Cache pressure
wiredTiger.cache "bytes read into cache" vs "maximum bytes configured"; cache defaults to 50 % of (RAM − 1 GB)
Backup
filesystem/volume snapshot or Atlas continuous backup for real clusters; mongodump only for small datasets
Upgrade path
one major at a time (7.0 → 8.0 → 8.3), replica set rolling, then raise FCV last so you can downgrade

Interview framing. "Add a shard" is not a capacity plan: resharding rewrites the collection, and until the balancer converges you have hot ranges. Say what you would measure first (write distribution per range, opcounters per shard, targeted vs scatter-gather ratio in $queryStats) and what you would do to buy time (zones, secondary reads, a bounded-array remodel).

08Security & encryption

Create a user
db.createUser({user:"app", pwd:passwordPrompt(), roles:[{role:"readWrite", db:"appdb"}]})
Auth mechanisms
SCRAM-SHA-256 (default) · MONGODB-X509 · MONGODB-OIDC (7.0) · LDAP/Kerberos (Enterprise)
Built-in roles
read readWrite dbAdmin dbOwner clusterMonitor clusterManager backup restore root
Custom role
db.createRole({role:"metrics", privileges:[{resource:{db:"appdb",collection:""}, actions:["find"]}], roles:[]})
Who am I
db.runCommand({connectionStatus:1, showPrivileges:true})
TLS
net.tls.mode: requireTLS + certificateKeyFile, CAFile; preferTLS only during a migration
Network
bindIp is 127.0.0.1 by default since 3.6 — keep it that way plus private IPs; never expose 27017
Encryption at rest
Enterprise/Atlas: WiredTiger encryption + KMIP / AWS KMS / Azure Key Vault / GCP KMS
CSFLE
client-side field level encryption, deterministic (equality) or random (opaque) — you manage the query support
Queryable Encryption
equality GA 6.0 · range GA 8.0 ($gt/$gte/$lt/$lte on ciphertext) · prefix/suffix/substring public preview 8.2
Server-side JS
$where, $function, $accumulator deprecated in 8.0 (server logs a warning); turn it off with security.javascriptEnabled: false
Auditing
Enterprise/Atlas; 8.0 added the OCSF audit-log schema for SIEM ingestion
Rate limiting (8.3)
pre-auth caps: preAuthMaximumMessageSizeBytes, capMemoryConsumptionForPreAuthBuffers, ingress request rate limiter

MongoBleed — CVE-2025-14847 (Dec 2025), exploited in the wild. Unauthenticated out-of-bounds read in zlib decompression of wire-protocol headers: an attacker who can open a socket leaks uninitialised heap memory — credentials, session tokens, API keys — with no login. Patch floor: 8.2.3, 8.0.17, 7.0.28, 6.0.27, 5.0.32, 4.4.30. Cannot patch yet? Remove zlib from net.compression.compressors and from every client URI (zstd/snappy are unaffected). ~87 000 internet-exposed servers were still unpatched at disclosure.

// Queryable Encryption: range query on ciphertext (GA in 8.0)
const encryptedFieldsMap = { "hr.employees": { fields: [
  { path: "salary", bsonType: "int", queries: { queryType: "range", min: 0, max: 1000000,
                                                sparsity: 1, contention: 4 } },
  { path: "ssn",    bsonType: "string", queries: { queryType: "equality" } }
] } };
// the driver rewrites this into an encrypted-index lookup; the server never sees plaintext
await db.collection("employees").find({ salary: { $gt: 90000, $lt: 150000 } }).toArray();

09Search, vector & hybrid

Three different engines: $text (in-server, crude), $search (Lucene), $vectorSearch (HNSW). Only the last two have a search index you define separately.

Availability
Atlas since 2020; Community & Enterprise self-managed in public preview from 8.2, self-managed search GA 2026-06-30 (Enterprise Advanced)
Manage indexes
db.c.createSearchIndex(name, type, definition) · db.c.getSearchIndexes() · db.c.dropSearchIndex(name)
Full text
{$search:{index:"default", text:{query:"laptop", path:["title","body"]}}} — must be the first stage
Facets/metadata
$searchMeta with facet; scores via {$meta:"searchScore"}
Vector (ANN)
{$vectorSearch:{index:"vec", path:"embedding", queryVector:[...], numCandidates:200, limit:10, filter:{tenant:"t1"}}}
Rule of thumb
numCandidates ≈ 10–20 × limit; drop it and set exact:true for small collections or ground truth
Similarity
cosine | dotProduct (normalise first) | euclidean; quantization scalar/binary to shrink the index
Hybrid, rank-based
$rankFusion — reciprocal rank fusion over named pipelines with weights (8.0; runs on views since 8.2)
Hybrid, score-based
$scoreFusion — combines raw normalised scores (public preview 8.2, GA 8.3)
8.3 extras
{$meta:"searchRootDocumentId"} for embedded-document hits; automated Voyage AI embeddings on write (public preview)
Legacy still fine
db.c.createIndex({title:"text"}) + {$text:{$search:"..."}} — one text index per collection, no analysers, no tuning
db.products.aggregate([{ $rankFusion: {
  input: { pipelines: {
    lexical: [ { $search: { index: "prod", text: { query: "wireless earbuds", path: "title" } } },
               { $limit: 50 } ],
    semantic: [ { $vectorSearch: { index: "prod_vec", path: "embedding",
                                   queryVector: qv, numCandidates: 500, limit: 50 } } ]
  } },
  combination: { weights: { lexical: 0.3, semantic: 0.7 } },
  scoreDetails: true
} }, { $limit: 10 }]);

10Gotchas & pitfalls

  • null matches both "field is null" and "field absent" — separate them with {$type:"null"} vs {$exists:false}.
  • $ne and $nin cannot narrow an index scan; rewrite as $in over the positive set where you can.
  • A $regex that is not anchored with ^ and case-sensitive scans the whole index.
  • An array field makes the index multikey — you cannot have two array fields in one compound index.
  • Mixing inclusion and exclusion in a projection throws; only _id may be excluded alongside inclusions.
  • An unindexed sort caps at 32 MB: Sort exceeded memory limit. Add the index, not allowDiskUse.
  • skip(n) walks n documents. Paginate by range on the sort key ({createdAt:{$lt:cursor}}), never by offset.
  • estimatedDocumentCount() ignores the filter and can be wrong after an unclean shutdown.
  • Money in a double loses cents — NumberDecimal, and check what your driver serialises by default.
  • Unbounded arrays grow the document toward 16 MB and every update rewrites the whole thing.
  • updateMany is not atomic across documents; another writer interleaves freely.
  • Transactions need a replica set — a single-node mongod refuses them (a one-member RS is fine locally).
  • A transaction past transactionLifetimeLimitSeconds (60 s) aborts; always inspect the commit result, never assume.
  • w:1 acknowledgements can be rolled back on failover — anything money-shaped is w:"majority".
  • Secondary reads without a causally consistent session return stale data silently; no error, no warning.
  • TTL deletion is a best-effort sweep every 60 s and is a normal delete: oplog volume and index churn included.
  • $out drops the target's indexes and neither $out nor $merge may run inside a transaction.
  • readConcern:"available" on a sharded cluster returns orphaned documents — never use it to count.
  • Case-insensitive uniqueness only works if the index and the query share the same collation.
  • One maxPoolSize=100 per serverless instance × 200 instances = a connection storm; pool per process, cap the fleet.
  • 8.3 changed pre-1970 $dateAdd/$dateSubtract results by one second for non-millisecond units.
  • 8.3 removed service from serverStatus and returns 10334 (BSONObjectTooLarge) on oversized upserts instead of 17419/17420 — dashboards and error handlers break quietly.
  • MongoDB has been SSPL-licensed since 2018 (Community Server); if a platform team asks "can we resell it", that is the answer they need.
