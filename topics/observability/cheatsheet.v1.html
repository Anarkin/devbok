Observability & prod debugging

cheatsheet · OTel Collector v1.66.0/v0.160.0 · Prometheus 3.14.0 · released 2026-09-02 / 2026-08-17

The vendor-neutral production stack on one card: the OTLP data model, SDK and Collector configuration, semantic-convention attribute names, the PromQL / LogQL / TraceQL typed under pressure, SLO burn-rate alerting, and the host, container, runtime and profiling commands reached for when something is on fire. Read as OpenTelemetry-centred open source rather than any one vendor's agent — Prometheus, Grafana Loki/Tempo/Pyroscope and the OTel Collector are the reference implementations, and the debugging half is Linux, Kubernetes and the four common runtimes. Verified 2026-09-08 against OTel Collector v1.66.0/v0.160.0 (2026-09-02), semconv v1.44.0, Prometheus 3.14.0 (2026-08-17) and Grafana 13.1; declarative SDK config went stable 2026-03-05 and the profiles signal is still alpha.

01Signals, data model & OTLP

docs: OpenTelemetry specification
Four signals
traces, metrics, logs — all stable API+SDK+OTLP; profiles alpha 2026-03, OTLP protocol still in development
OTLP transports
gRPC :4317 · HTTP :4318 with paths /v1/traces, /v1/metrics, /v1/logs, /v1/profiles
Pick the protocol
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf (also grpc, http/json) — http/protobuf survives proxies and service meshes best
Resource
the entity emitting telemetry; service.name is the one required attribute, plus service.namespace, service.version, service.instance.id, deployment.environment.name
Scope
instrumentation library name+version on every span/metric/log — how you tell your spans from the framework's
Span
trace_id (16 B) · span_id (8 B) · parent · name · kind SERVER|CLIENT|PRODUCER|CONSUMER|INTERNAL · status UNSET|OK|ERROR · attributes · events · links
Span name rule
low cardinality: GET /orders/{id}, never GET /orders/8123 — the id goes in an attribute
Metric instruments
Counter, UpDownCounter, Histogram, Gauge (sync) and Observable* callbacks (async)
Temporality
OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE=delta|cumulative|lowmemory — Prometheus wants cumulative; most SaaS want delta
Exemplar
a trace_id attached to a histogram bucket sample — the click-through from “p99 is bad” to one slow trace
Log record
body, severity_number (1–24) / severity_text, attributes, plus trace_id/span_id injected by the log bridge
Context propagation
W3C traceparent: 00-{32 hex trace}-{16 hex span}-01, plus tracestate and baggage; last hex byte is the sampled flag
Choose the propagator
OTEL_PROPAGATORS=tracecontext,baggage (default) — add b3multi or xray only while migrating
Entities
the successor model for resources (host, k8s pod, service) so backends can key telemetry by identity; still in development in the spec

The three-pillars framing is out of date on purpose: one event with high-cardinality attributes, wide enough to slice after the fact, is the modern unit. Metrics are pre-aggregated cheapness, traces are causality, logs are detail — you correlate them by trace_id, not by timestamp.

03Semantic conventions

docs: semantic conventions v1.44.0
Why it matters
stable attribute names are what make a dashboard portable between backends and a query work across four languages
HTTP server span stable
http.request.method, http.response.status_code, http.route, url.path, url.query, url.scheme, server.address, client.address, network.protocol.version, user_agent.original
Errors
error.type — exception class or status code, low cardinality; on spans also exception.type / exception.message / exception.stacktrace as a span event
Database
db.system.name, db.namespace, db.collection.name, db.operation.name, db.query.text (parameterised, never the values), db.response.status_code
Messaging
messaging.system, messaging.destination.name, messaging.operation.type=publish|receive|process
The three metrics to know
http.server.request.duration (histogram, seconds), http.client.request.duration, db.client.operation.duration
Kubernetes / infra
k8s.namespace.name, k8s.pod.name, k8s.deployment.name, k8s.node.name, container.id, host.name, cloud.region
GenAI moved out semconv v1.42
all gen_ai.* now live in open-telemetry/semantic-conventions-genai (repo created 2026-05-05) and are still Development, not stable — do not build contracts on them
Legacy names still seen
http.method, http.status_code, http.url, net.peer.name, db.statement — pre-1.21 spellings, still emitted by old agents
Migrate safely
OTEL_SEMCONV_STABILITY_OPT_IN=http/dup emits both spellings for one release so dashboards can cut over
Custom attributes
own namespace (acme.order.tier), never a bare id; validate and generate constants with Weaver
Version pinning
emit schema_url so backends can apply schema transformations across semconv versions

04Collector & OTTL

docs: Collector configuration
Versions
stable modules v1.66.0, beta modules v0.160.0 (2026-09-02); one release roughly every two weeks
Distributions
otelcol (core) · otelcol-contrib (everything) · otelcol-k8s · otelcol-ebpf-profiler; roll your own with the builder ocb --config builder.yaml
Topology
agent (DaemonSet/sidecar, enriches with host+pod) → gateway (StatefulSet, batches, tail-samples, exports) — tail sampling needs whole traces in one instance
Pipeline order
memory_limiter first, then k8sattributes/resourcedetection, then transform/filter, batching last before the exporter
Batching moved
prefer the exporter's sending_queue.batch over the standalone batch processor in current builds — it batches after the queue, so retries do not re-batch
Connectors
spanmetrics (RED metrics from spans), servicegraph, routing, count, forward — a pipeline's exporter feeding another pipeline's receiver
Trace affinity
loadbalancing exporter with routing_key: traceID in front of tail-sampling gateways
Health & debug
extensions health_check (:13133), pprof (:1777), zpages (:55679/debug/tracez); own metrics on :8888/metrics
The four metrics to watch
otelcol_receiver_refused_spans, otelcol_exporter_send_failed_spans, otelcol_exporter_queue_size vs _capacity, otelcol_processor_dropped_*
See the data
exporters: debug: { verbosity: detailed } — replaced the removed logging exporter
Validate a config
otelcol validate --config=config.yaml · run with --feature-gates=+component.UseLocalHostAsDefaultHost awareness on containers
Profiles support
pprof receiver, profiles in k8sattributes and OTTL since v0.148.0 2026-03
receivers:
  otlp: { protocols: { grpc: { endpoint: 0.0.0.0:4317 }, http: { endpoint: 0.0.0.0:4318 } } }
processors:
  memory_limiter: { check_interval: 1s, limit_percentage: 80, spike_limit_percentage: 20 }
  k8sattributes: { auth_type: serviceAccount, passthrough: false }
  transform:                                   # OTTL
    error_mode: ignore
    trace_statements:
      - set(span.status.code, STATUS_CODE_ERROR) where span.attributes["http.response.status_code"] >= 500
      - delete_key(span.attributes, "http.request.header.authorization")
      - replace_pattern(span.attributes["url.path"], "/orders/[0-9]+", "/orders/{id}")
  tail_sampling:
    decision_wait: 10s
    policies:
      - { name: errors,  type: status_code, status_code: { status_codes: [ERROR] } }
      - { name: slow,    type: latency,     latency: { threshold_ms: 1000 } }
      - { name: sample,  type: probabilistic, probabilistic: { sampling_percentage: 5 } }
connectors:
  spanmetrics: { histogram: { explicit: { buckets: [5ms, 25ms, 100ms, 500ms, 2s] } } }
exporters:
  otlphttp: { endpoint: https://backend:4318, sending_queue: { batch: { flush_timeout: 5s } } }
service:
  pipelines:
    traces:  { receivers: [otlp], processors: [memory_limiter, k8sattributes, transform, tail_sampling], exporters: [otlphttp, spanmetrics] }
    metrics: { receivers: [otlp, spanmetrics], processors: [memory_limiter], exporters: [otlphttp] }
  telemetry: { metrics: { level: normal } }

05Metrics & PromQL

docs: PromQL
Request rate (RED)
sum by (http_route) (rate(http_server_request_duration_seconds_count[5m]))
Error ratio
sum(rate(...count{http_response_status_code=~"5.."}[5m])) / sum(rate(...count[5m]))
Classic histogram p99
histogram_quantile(0.99, sum by (le, http_route) (rate(http_server_request_duration_seconds_bucket[5m])))
Native histogram p99 Prom 3.8 stable
histogram_quantile(0.99, sum by (http_route) (rate(http_server_request_duration_seconds[5m]))) — no le, no bucket suffix; also histogram_count, histogram_sum, histogram_fraction(0, 0.5, ...)
Enable native histograms
scrape_native_histograms: true per scrape config (v3.8+; the old --enable-feature=native-histograms is a no-op from v3.9, and both scrape and remote-write default to true in v4.0)
Classic → native at scrape
convert_classic_histograms_to_nhcb: true — custom-bucket native histograms (schema −53) keep your existing buckets at a fraction of the series count
Saturation (USE)
rate(container_cpu_cfs_throttled_seconds_total[5m]) · container_memory_working_set_bytes / container_spec_memory_limit_bytes
Restart / crashloop
increase(kube_pod_container_status_restarts_total[15m]) > 0
Scrape health
up == 0, absent(up{job="api"}), scrape_samples_post_metric_relabeling, prometheus_target_scrape_pool_exceeded_sample_limit_total
Cardinality hunt
topk(10, count by (__name__)({__name__=~".+"})) · promtool tsdb analyze /prometheus · TSDB Status page
Aggregation rules
sum by keeps listed labels, sum without drops them; rate() needs ≥2 samples so use ≥4× the scrape interval; never avg() a quantile
Counter reset
rate/increase correct for resets; irate only for fast-moving graphs, never for alerts
Prediction / trend
predict_linear(node_filesystem_avail_bytes[6h], 4*3600) < 0 — the disk-full alert that pages before it happens
OTLP into Prometheus 3.0
POST to /api/v1/otlp/v1/metrics, enabled by --web.enable-otlp-receiver; UTF-8 names allowed, quoted as {"http.server.duration"}; control suffixes with otlp.translation_strategy
Remote-Write 2.0 3.0
carries metadata, exemplars, native histograms and start timestamps in one protobuf; 1.0 senders keep working
New in 3.14 2026-08-17
rate()/increase() can extrapolate from series start timestamps behind --enable-feature=use-start-timestamps, killing the classic first-scrape undercount
Command line
promtool check config prometheus.yml · promtool check rules rules.yml · promtool query instant http://localhost:9090 'up' · promtool test rules tests.yml
# Recording rule: pre-compute what every dashboard panel and SLO alert re-derives.
groups:
  - name: sli
    interval: 30s
    rules:
      - record: job:http_requests:rate5m
        expr: sum by (job) (rate(http_server_request_duration_seconds_count[5m]))
      - record: job:http_errors:ratio5m
        expr: |
          sum by (job) (rate(http_server_request_duration_seconds_count{http_response_status_code=~"5.."}[5m]))
            / sum by (job) (rate(http_server_request_duration_seconds_count[5m]))

06Logs & LogQL

docs: LogQL
Stream selector first
{app="checkout", namespace="prod"} — labels are the index; everything after the first | is a scan, so keep labels few and bounded
Line filters
|= "timeout" (contains) · != "healthz" · |~ "(?i)err(or)?" (regex) · !~; cheapest filter goes first
Parsers
| json · | logfmt · | pattern "<_> <method> <path> <status>" · | regexp "(?P<status>\\d{3})"
Label filters & shaping
| status >= 500 | duration > 2s · | label_format route=path · | line_format "{{.route}} {{.duration}}" · | drop __error__
Logs → metrics
sum by (status) (rate({app="checkout"} | json | __error__="" [5m])) · quantile_over_time(0.99, {app="x"} | json | unwrap duration_ms [5m])
Find the trace
{app="checkout"} | json | trace_id="4bf92f3577b34da6a3ce929d0e0e4736" — store trace_id as structured metadata, not as a label
Structured metadata Loki 3.0
per-line key/values (trace_id, pod, request_id) that are queryable without being indexed labels — the fix for cardinality-driven log stores
OTLP ingest
Loki accepts OTLP logs at /otlp/v1/logs 3.0; resource attributes become labels, the rest become structured metadata
Shipper
Grafana Alloy (loki.source.* + loki.process); Promtail is EOL 2026-03-02 — migrate with alloy convert --source-format=promtail --output=config.alloy promtail.yml
App-side rules
one structured event per unit of work; log at the boundary, not in the loop; include trace_id, service.name, error.type; never log secrets or PII
Severity discipline
ERROR = a human must look; WARN = degraded but handled; INFO = state transitions; DEBUG off in prod, flipped on per-service by config, not by redeploy
Grep-equivalents on a box
journalctl -u api -S "10 min ago" -p err -f · kubectl logs -f deploy/api --since=10m --all-containers · jq -r 'select(.level=="error") | .msg'
Cost control
sample repetitive INFO lines, drop health checks at the agent, keep 100% of ERROR; retention by tenant, not by hope

07Traces, TraceQL & sampling

docs: TraceQL
Slow or failed requests
{ resource.service.name = "checkout" && span.http.response.status_code >= 500 } · { duration > 2s }
Aggregate over a trace
{ span.db.system.name = "postgresql" } | count() > 20 — the N+1 query finder
Structural operators
> direct child, >> descendant, ~ sibling: { name="POST /checkout" } >> { status = error }
Trace-level filters
{ } | by(resource.service.name) | count() > 3 · select(span.db.query.text) to pull extra fields into results
Head sampling
decided at the root, propagated by the sampled flag; cheap, consistent, blind to what happens later
Tail sampling
Collector buffers a trace for decision_wait then applies policies (latency, status_code, probabilistic, string_attribute, composite); keeps all errors, drops the boring 95%
Consistent probability
the sampling threshold rides in tracestate as ot=th:… so every hop and the backend can compute the correct span count after sampling
Never sample your metrics
generate RED metrics with the spanmetrics connector before tail sampling, or your error rate is a 5% estimate
Correlate
metric → trace via exemplars; log → trace via trace_id; trace → profile via span-scoped profiling; Grafana data links wire the three together
Span links
for async fan-out and batch consumers where a parent-child edge would lie (one consumer span, N producer links)
Broken propagation checklist
proxy/CDN header allowlist missing traceparent · a queue that drops headers · mixed W3C and B3 · a thread pool or Task.Run that loses context · a client library instrumented but not the transport
Backends
Grafana Tempo 2.10/3.0 (2.9 support ends 2026-12-31), Jaeger v2 (itself an OTel Collector distribution), ClickHouse-backed stores; all speak OTLP

08SLOs & burn-rate alerts

docs: SRE workbook, alerting on SLOs
SLI
good events / valid events — availability, latency (fraction under a threshold), freshness, correctness. Measure where the user is, not where the server is
Error budget
1 − SLO. 99.9% over 30 days = 43m 12s of budget; 99.95% = 21m 36s; 99.99% = 4m 19s
Burn rate
how many times faster than budgeted you are spending: burn = observed error ratio / (1 − SLO). 1× uses exactly the budget in the window
Latency SLI in PromQL
sum(rate(..._bucket{le="0.5"}[5m])) / sum(rate(..._count[5m])) — fraction faster than 500 ms, not a percentile
Multiwindow, multi-burn
long window catches the sustained burn, short window confirms it is still happening — that pairing is what stops flapping pages
Alert on symptoms
page on user-visible burn; make cause-based signals (queue depth, CPU) ticket-level or dashboard-only
Rule hygiene
for: to debounce, keep_firing_for: to stop resolve-flapping, runbook URL and owner in annotations, severity in labels
Generate, do not hand-write
Sloth, Pyrra or OpenSLO turn one SLO spec into all four burn-rate rules plus recording rules
Budget policy
the useful half is the agreement: budget exhausted → feature freeze until it recovers. An SLO nobody acts on is a dashboard
Budget spentLong windowShort windowBurn rateAction

5%6h30m6×page

09Host & container triage

docs: debug a running pod
60-second checklist
uptime → dmesg -T | tail → vmstat 1 → mpstat -P ALL 1 → pidstat 1 → iostat -xz 1 → free -m → sar -n DEV 1 → sar -n TCP,ETCP 1 → top
Read it
vmstat: r > cores = CPU saturation, si/so ≠ 0 = swapping. iostat: %util near 100 with high await = disk-bound
Who is eating CPU
pidstat -t 1 (per thread) · top -H -p PID · perf top -p PID
Sockets & connections
ss -s summary · ss -tanp state established '( dport = :5432 )' · ss -lntp listeners · check Send-Q backlog on accept queues
Packet truth
tcpdump -ni any port 5432 -c 200 -w /tmp/db.pcap · tcpretrans / tcpconnect (bcc) for retransmits and connect latency
Files & descriptors
lsof -p PID | wc -l vs cat /proc/PID/limits · ls /proc/PID/fd | wc -l — the classic slow leak
Syscall level
strace -f -p PID -T -e trace=network,file -o /tmp/s.txt — pauses the process; sample briefly, never on a hot path in prod
Ephemeral debug container
kubectl debug -it pod/api-7f8 --image=nicolaka/netshoot --target=api GA K8s 1.25 — shares the PID/network namespace of a distroless container
Copy-and-poke a pod
kubectl debug pod/api-7f8 --copy-to=api-dbg --set-image=api=busybox -it — leaves the live pod untouched
Node shell
kubectl debug node/node-1 -it --image=busybox → host FS under /host
Crash forensics
kubectl logs pod/x --previous · kubectl describe pod x (Last State, Reason) · kubectl events --for pod/x --watch
OOM vs throttle
exit code 137 + Reason OOMKilled = memory limit; slow-but-alive with rising container_cpu_cfs_throttled_seconds_total = CPU limit. Exit 143 = SIGTERM, usually a rollout
Runtime, below kubelet
crictl ps -a · crictl logs -f <id> · crictl inspect <id> | jq .status.exitCode
Resource reality
kubectl top pod --containers · kubectl get --raw /api/v1/nodes/node-1/proxy/metrics/resource
DNS in the cluster
kubectl run -it --rm dns --image=nicolaka/netshoot -- dig +search api.prod.svc.cluster.local; check ndots:5 before blaming CoreDNS
Rollback first
kubectl rollout undo deploy/api — mitigate, then debug the artefact you saved, not the incident

11Profiling & eBPF

docs: OTel profiles
Continuous profiling
always-on sampled stacks (CPU, alloc, lock, off-CPU) at ~1–5% overhead — answers “which function costs the money” without a repro
OTel profiles alpha 2026-03
fourth signal, pprof-compatible, round-trips losslessly and cuts wire size ~40% with a shared string dictionary; Collector support from v0.148.0 (pprof receiver, k8sattributes, OTTL). Not for critical workloads yet
OBI
OpenTelemetry eBPF Instrumentation — Grafana Beyla donated in 2025, v0.8.0 2026-04-16, beta announced at KubeCon EU 2026-04, 1.0 the project's 2026 goal. Zero-code HTTP/gRPC/SQL traces and RED metrics, no restart, no code change
OBI requirements
Linux ≥5.8 with BTF, CAP_BPF+CAP_PERFMON (or privileged), one agent per node; .NET support on the roadmap
Ad-hoc CPU flame graph
perf record -F 99 -a -g -- sleep 30 → perf script | stackcollapse-perf.pl | flamegraph.pl > cpu.svg
Read a flame graph
width = time on CPU, x-axis is alphabetical not chronological; look for wide plateaus, ignore tall thin towers
Off-CPU time
offcputime-bpfcc -df 30 — where threads block (locks, I/O), the half a CPU profile cannot see
bcc one-liners
execsnoop · opensnoop · biolatency · runqlat (scheduler delay) · tcpretrans · profile -F 49 -p PID 30
bpftrace
bpftrace -e 'tracepoint:syscalls:sys_enter_openat { @[comm] = count(); }' · bpftrace -l 'tracepoint:*' to discover probes
Stores
Grafana Pyroscope, Parca, Polar Signals; symbolisation needs debug symbols shipped or an uploaded symbol store — plan it before the incident
Symbolisation gotcha
stripped binaries and JIT runtimes give hex addresses; JVM needs -XX:+PreserveFramePointer, Node needs --perf-basic-prof

12Idioms & gotchas

docs: instrumentation concepts
  • Cardinality kills metrics, not traces. user id, request id, full URL belong in span and log attributes; a metric label must have bounded values.
  • Every label multiplies. 5 routes × 6 statuses × 3 pods × 12 buckets = 1 080 series from one histogram — budget before you add a dimension.
  • Never average a percentile. Aggregate histogram buckets, then compute the quantile; avg(p99) is a number with no meaning.
  • Classic bucket boundaries are forever. Changing le values breaks historical quantiles; native histograms exist precisely to end that argument.
  • Derive RED before sampling. The spanmetrics connector must sit ahead of tail_sampling, or counts are a sampled guess.
  • Tail sampling needs trace affinity. Without the loadbalancing exporter, gateway replicas each see partial traces and decide differently.
  • memory_limiter goes first. Any processor before it can OOM the Collector it was meant to protect.
  • Cumulative vs delta mismatch shows up as sawtooth graphs or flat zeros — check OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE against what the backend expects.
  • OTLP → Prometheus renames things. Suffixes (_total, _seconds) and dot-to-underscore escaping are applied on ingest; pick a translation_strategy once and keep it.
  • rate() over too short a range returns nothing. Use ≥4× the scrape interval; a 1m range on a 30s scrape is a flapping alert.
  • Alert on absence too. A crashed exporter looks like zero errors — pair every ratio alert with absent() or up == 0.
  • Missing traceparent is usually a proxy. CDN, WAF and API-gateway header allowlists strip unknown headers by default.
  • Async loses context silently. Fire-and-forget tasks, thread pools and queue consumers need explicit context extraction or span links.
  • Health checks pollute everything. Drop /healthz and /metrics at the agent, before they distort the latency histogram and the log bill.
  • Secrets leak through attributes. Strip http.request.header.authorization, query-string tokens and raw SQL values in the Collector, not in review.
  • Clock skew produces negative durations. Trust the span's own duration, not the difference of two hosts' timestamps.
  • Debug logging is a config flag, not a deploy. If turning on DEBUG needs a release, you will never turn it on during the incident.
  • Mitigate before you diagnose. Roll back, shift traffic, raise a limit — then debug the saved dump, trace and profile.
  • Instrument the client too. Server-side p99 excludes DNS, TLS, retries and queueing — the parts users actually feel.
  • Observability has a bill. Telemetry cost frequently exceeds the workload's; sample traces, sample INFO logs, keep 100% of errors and metrics.
