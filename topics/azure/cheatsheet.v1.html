01Resource model & scopes

docs: Azure Resource Manager

Everything is an ARM resource with a canonical ID. Learn the ID shape and half of Azure debugging is reading a string.

/subscriptions/{subId}/resourceGroups/{rg}/providers/{RP}/{type}/{name}[/{childType}/{childName}]
/subscriptions/00000000-0000-0000-0000-000000000000/resourceGroups/rg-app-prod-weu/providers/Microsoft.Web/sites/app-orders
Scope hierarchy
tenant → management group (6 levels max under root) → subscription → resource group → resource. RBAC, Policy and deployments all target a scope and inherit downward; nothing inherits sideways.
Resource group
a lifecycle + region-of-metadata boundary, not a security or network boundary. Resources may live in other regions than their RG. Delete the RG, delete the contents.
Subscription
the billing and quota boundary. Most limits (cores per region, public IPs, ARM writes) are per subscription per region — the usual reason to split, along with blast radius.
Provider / API version
every write pins an API version: Microsoft.Web/sites@2024-11-01. New properties simply do not exist on older versions — the #1 cause of “the portal can do it, my template can’t”.
Tags
50 per resource, 512-char names, 256-char values; not inherited by default — use Policy modify with inheritTagFromResourceGroup.
Locks
CanNotDelete and ReadOnly, inherited to children. ReadOnly breaks control-plane operations that look like reads (listing storage keys is a POST) — prefer CanNotDelete.
Correlation on failure
every ARM error carries a x-ms-correlation-request-id; quote it in support cases and join on it in Activity Log.

Naming, regions, moves

  • Global-unique names: storage accounts (3–24, lowercase alphanumeric), Key Vault (3–24), App Service (*.azurewebsites.net), ACR, Cosmos DB, Service Bus namespaces. Everything else is unique per RG.
  • Availability zones are per-subscription logical mappings; zone 1 in your subscription is not zone 1 in mine. Use az vm list-skus --location westeurope --zone to see real capability.
  • Move: az resource move --destination-group — source and target are locked for the duration; many resources (VNets with peerings, Key Vault with keys in use, ASE, managed identities) cannot move. Redeploying via IaC is usually faster than fighting a move.
  • Soft delete is on and non-optional for Key Vault (90 days default) and recoverable for Storage blobs/containers if enabled — a redeploy under the same name will fail with ConflictError until purged.

Lead framing: pick the boundary by what you want to fail independently. One subscription per environment per platform team is the common landing-zone default; per-team subscriptions when quota or policy needs differ; RGs only for lifecycle grouping.

02Azure CLI daily driver

docs: az reference

Azure CLI 2.90.0 2026-09-01. Every az command is az <group> <subgroup> <verb>, returns JSON, and supports --query (JMESPath) and --output.

# sign in and pin context (interactive login now requires MFA for write ops)
az login --tenant contoso.onmicrosoft.com
az account set --subscription "prod-platform"
az account show --query "{sub:name, id:id, tenant:tenantId}" -o table

# the four flags that matter
az webapp list -o table                       # human table
az webapp list --query "[?state=='Running'].name" -o tsv    # scriptable
az group create -n rg-demo -l westeurope --tags env=dev owner=me
az vm create -g rg-demo -n vm1 --image Ubuntu2404 --no-wait  # fire and forget

# JMESPath you will actually reuse
az vm list --query "[].{name:name, size:hardwareProfile.vmSize, rg:resourceGroup}" -o table
az role assignment list --all --query "[?principalName=='svc-deploy'].roleDefinitionName" -o tsv
az resource list --tag env=prod --query "[].id" -o tsv | xargs -n1 az resource show --ids

# generic escape hatch when a command group lags the API
az resource update --ids $ID --set properties.publicNetworkAccess=Disabled
az rest --method get --url "https://management.azure.com$ID?api-version=2024-11-01"
Config once, save typing
az config set defaults.group=rg-demo defaults.location=westeurope core.output=table core.only_show_errors=true
Extensions
az extension add --name containerapp; az extension update --all; az config set extension.dynamic_install_allow_preview=true. Extensions version independently of the CLI — a “command not found” is usually a missing or stale extension.
Deployment / async
--no-wait then az resource wait --ids $ID --created / --custom "properties.provisioningState=='Succeeded'".
Debugging a failure
az deployment operation group list -g rg -n dep --query "[?properties.provisioningState=='Failed'].properties.statusMessage" — the top-level error is always useless; the operation list has the real one.
Activity log (who did it)
az monitor activity-log list -g rg --start-time 2026-09-07T00:00Z --query "[].{op:operationName.value, by:caller, status:status.value}" -o table
New in 2.90.0
az webapp exec (interactive shell into a Linux container app), az aks nodepool auto-scale add/update/delete, Key Vault control plane on API 2026-02-01, NAT64 on StandardV2 NAT gateways.
New in 2.88.0 2026-07
az functionapp flex-migration (Linux Consumption → Flex), az aks nodepool get-rollback-versions/rollback; default VM --size changed Standard_DS1_v2 → Standard_D2s_v5; Linux is the default OS for az webapp create unless --hyper-v.
Breaking in 2.92.0 2026-11
az blueprint is removed (Blueprints are deprecated — move to deployment stacks / Azure Landing Zones), and --access-keys-auth flips its default from Enabled to Disabled.
PowerShell equivalent
Az 16.3.0 2026-08-31: Connect-AzAccount, Set-AzContext -Subscription, Get-AzResource -Tag @{env='prod'}. AzureRM has been retired since 2024-02-29 — any *-AzureRm* cmdlet in a repo is dead code.

Automation gotcha: az login in CI must be non-interactive — OIDC federation (az login --service-principal --username $CLIENT_ID --tenant $TENANT --federated-token $TOKEN) or a managed identity (az login --identity). Client secrets in pipeline variables are the legacy pattern.

03Bicep, deployment stacks & azd

docs: Bicep

Bicep 0.46.1 2026-07-31 is the first-party IaC language; ARM JSON is its compile target, not something you hand-write any more.

targetScope = 'resourceGroup'

@description('Short environment name')
@allowed(['dev', 'test', 'prod'])
param env string
param location string = resourceGroup().location
@secure()
param sqlAdminPassword string

var name = 'app-orders-${env}-${uniqueString(resourceGroup().id)}'

resource plan 'Microsoft.Web/serverfarms@2024-11-01' = {
  name: 'plan-${env}'
  location: location
  sku: { name: env == 'prod' ? 'P1v4' : 'B1' }
  properties: { reserved: true }   // reserved: true == Linux
}

@retryOn(['ResourceDeploymentFailure'], 3)   // 0.43+ : retry a flaky resource
resource site 'Microsoft.Web/sites@2024-11-01' = {
  name: name
  location: location
  identity: { type: 'SystemAssigned' }
  properties: {
    serverFarmId: plan.id
    httpsOnly: true
    siteConfig: { minTlsVersion: '1.2', ftpsState: 'Disabled', netFrameworkVersion: 'v10.0' }
  }
}

module kv 'br/public:avm/res/key-vault/vault:0.11.0' = {
  name: 'kv'
  params: { name: 'kv-${env}-${uniqueString(resourceGroup().id)}', location: location, enableRbacAuthorization: true }
}

output principalId string = site.identity.principalId
output url string = 'https://${site.properties.defaultHostName}'
Preview a change
az deployment group what-if -g rg -f main.bicep -p main.bicepparam — the single most useful command in the toolchain. --result-format FullResourcePayload when the summary lies.
Deploy
az deployment group create -g rg -f main.bicep -p main.bicepparam -n rel-$(date +%s). Default mode is Incremental (nothing is deleted); --mode Complete deletes anything in the RG not in the template.
Deployment stacks GA 2024
the modern answer to “who cleans up?”: az stack group create -g rg -n app -f main.bicep --action-on-unmanage deleteAll --deny-settings-mode denyDelete. The stack owns its resources, removes ones that leave the template, and can deny out-of-band changes. This is what replaced Blueprints.
Params file
.bicepparam (not JSON): using 'main.bicep' then param env = 'prod'; getSecret() pulls from Key Vault at deploy time. extends layers a base param file; inherited params are optional since 2026-07.
Modules & AVM
prefer Azure Verified Modules from the public registry: br/public:avm/res/<service>/<resource>:<ver>. Private registry: az bicep publish --file m.bicep --target br:myacr.azurecr.io/bicep/m:1.0.0.
Newer language bits
like() and distinct() 0.43.1, 2026-05; user-defined types (type sku = { name: string }) and functions; import/export across files; bicep snapshot GA 0.41.2, 2026-03 for a normalised, diffable view of what a file will produce.
Lint & format
az bicep lint --file main.bicep, az bicep format; rules in bicepconfig.json. The secure-params-in-parameters-file rule 2026-07 catches secrets checked into .bicepparam.
Terraform interop
plenty of shops run Terraform with azurerm (and azapi for un-covered resources). Both are fine; the argument to win in an interview is state management and drift, not syntax.

azd — the app-centric wrapper

azd init --template todo-csharp-cosmos-sql   # azure.yaml + infra/ (Bicep)
azd auth login --federated-credential-provider azure-pipelines
azd up            # provision + build + deploy, one command
azd provision --preview                      # what-if for the whole environment
azd env set AZURE_LOCATION westeurope && azd env list
azd pipeline config --provider github        # writes OIDC federated creds, no secrets

azd 1.32.0 2026-08: the extension framework went GA, Azure Functions can deploy a prebuilt container image (no local Docker step), and provisioning infers Bicep dependencies in layers. Use azd for greenfield app+infra repos; plain Bicep or Terraform for platform/landing-zone code.

04Identity & managed identity

docs: Managed identities

Two planes, two token audiences: Entra ID issues tokens; ARM authorises control-plane calls; each data plane (Storage, Key Vault, SQL…) has its own resource URI and its own RBAC.

System-assigned MI
1:1 with the resource, dies with it. Zero secrets. az webapp identity assign -g rg -n app → returns principalId.
User-assigned MI preferred at scale
its own resource, attach to many; survives redeploys, so role assignments are created once and stay valid. az identity create -g rg -n id-orders, then az webapp identity assign --identities $UAMI_ID. Also the way to pre-create the principal before granting.
Workload identity federation
no secrets for GitHub Actions / Azure DevOps / AKS / other clouds: az identity federated-credential create --identity-name id-ci -g rg --issuer https://token.actions.githubusercontent.com --subject repo:org/repo:ref:refs/heads/main --audiences api://AzureADTokenExchange. This is the modern replacement for SP client secrets and certificates.
AKS workload identity
projected service-account token federated to a UAMI — replaces the retired AAD Pod Identity (retired 2023-09). New in CLI 2.89.0: az aks identity-binding for trust-domain based binding.
App registration vs enterprise app
one application object (global, in its home tenant) + one service principal per tenant. Role assignments and consent hang off the service principal; API permissions off the application. Interview answer: “app registration is the blueprint, the enterprise app is the instance.”
Token endpoint (IMDS)
GET http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https://vault.azure.net with header Metadata: true. On App Service/Functions/ACA it is IDENTITY_ENDPOINT + IDENTITY_HEADER instead — the SDK handles both.
Easy Auth
App Service / Container Apps built-in auth: platform validates the token before your code runs, injects X-MS-CLIENT-PRINCIPAL* headers, /.auth/me returns claims. Free SSO, but it is authentication only — authorisation is still yours.
MFA at the ARM layer enforced
since phase 2 (rollout from 2025-10-01, last postponement window ended 2026-07-01), any create/update/delete through CLI, PowerShell, REST, SDKs or IaC requires MFA; reads do not. Needs az ≥ 2.76 / Az ≥ 14.3. Service principals and managed identities are unaffected — which is another reason CI should not use user credentials.

Rule of thumb: a connection string in app settings is a finding. The only acceptable secrets left are third-party API keys, and those live in Key Vault referenced by a managed identity.

05RBAC, ABAC & Policy

docs: Azure RBAC 
# grant, always by resource id, always least-privilege
az role assignment create --assignee-object-id $PRINCIPAL_ID --assignee-principal-type ServicePrincipal \
  --role "Storage Blob Data Contributor" --scope $STORAGE_ID

# who has what, here and above
az role assignment list --scope $ID --include-inherited --include-groups -o table
az role definition list --name "Key Vault Secrets User" --query "[0].permissions" -o json

# custom role: start from a built-in, trim, then create
az role definition create --role-definition @role.json
The five you use daily
Storage Blob Data Contributor, Key Vault Secrets User, AcrPull, Azure Service Bus Data Sender/Receiver, Monitoring Metrics Publisher. Note the pattern: control-plane roles (Contributor) never grant data-plane access.
Owner vs Contributor vs UAA
Contributor cannot grant roles; User Access Administrator can grant but not manage resources; Role Based Access Control Administrator is the narrower modern grant-only role — prefer it over UAA.
ABAC conditions
attach a condition to a data-plane assignment so it applies to a blob path or tag: --condition "@Resource[Microsoft.Storage/storageAccounts/blobServices/containers:name] StringEquals 'public'" --condition-version 2.0. Avoids inventing a role per container.
Deny assignments
read-only to you: created by Azure Managed Applications, Blueprints (deprecated) and deployment stacks’ denySettings. Deny beats allow, always.
PIM
eligible ≠ active. Standing Owner on prod is the finding; PIM activation with approval + justification + max duration is the answer. Entra ID P2.
Propagation
role assignments take up to ~5 minutes (occasionally 30) to reach every data plane. In IaC, a deploy that assigns a role and immediately uses it flakes — hence Bicep’s @retryOn and CLI 2.88’s fix to set principalType so fresh principals do not fail PrincipalNotFound.
Limits
4 000 role assignments per subscription (5 000 with the higher-limit flag), 5 000 custom roles per tenant. Assign to groups, not users.

az policy assignment create --name deny-public-blob --scope $MG \
  --policy /providers/Microsoft.Authorization/policyDefinitions/13502221-8df0-4414-9937-de9c5c4e396b
az policy state summarize --resource-group rg --query "value[0].results" -o json

Initiatives (policy sets) are how you ship: Microsoft Cloud Security Benchmark is assigned by default via Defender for Cloud; regulatory initiatives (PCI, ISO 27001, NIST 800-53) are add-ons. Exemptions are time-boxed and owned; a permanent exemption is a policy that should be rewritten.

App Service

# blue/green that actually warms up
az webapp deployment slot create -g rg -n app-orders --slot staging
az webapp deploy -g rg -n app-orders --slot staging --src-path app.zip --type zip --tag "rel-142"
az webapp traffic-routing set -g rg -n app-orders --distribution staging=10   # canary

  • Premium v4 (P*v4) is GA and the current recommended production tier; Isolated v4 on ASEv3 went GA at Build 2026. Pv2 is legacy pricing/hardware.
  • Slot settings: mark an app setting “deployment slot setting” (--slot-settings) or it swaps with the code — the classic “staging now points at the prod database” incident.
  • A swap restarts the target instances; WEBSITE_SWAP_WARMUP_PING_PATH + Always On avoid a cold first request.
  • Sidecars (Linux) attach extra containers for OTel collectors, caches or local inference next to the main app.

Azure Functions

az functionapp create -g rg -n fn-orders --flexconsumption-location westeurope \
  --runtime dotnet-isolated --runtime-version 10 --storage-account stfnorders \

// .NET 10 isolated worker: the only supported model going forward
public class OrderFunctions(ILogger<OrderFunctions> log, ServiceBusClient bus)
{
    [Function(nameof(OnOrderPlaced))]
    public async Task OnOrderPlaced(
        [ServiceBusTrigger("orders", "billing", Connection = "Bus")] ServiceBusReceivedMessage msg,
        CancellationToken ct)
    {
        log.LogInformation("order {Id}", msg.MessageId);
        await Task.CompletedTask;
    }

    [Function("Health")]
    public IActionResult Health([HttpTrigger(AuthorizationLevel.Anonymous, "get")] HttpRequest req)
        => new OkObjectResult("ok");
}
// Connection = "Bus" resolves Bus__fullyQualifiedNamespace for identity-based binding (no connection string)
  • In-process .NET ends support 2026-11-10 — two months out. Isolated worker is the only model with .NET 10; migration is mostly FunctionName→Function, Startup→Program.cs, and swapping Microsoft.Azure.WebJobs.* for Microsoft.Azure.Functions.Worker.*.
  • Flex Consumption is the modern serverless plan: scale-to-zero with VNet integration, per-instance memory choice (512 MB–4 GB), per-function scaling and alwaysReady instances for cold-start-sensitive endpoints. Linux Consumption is being retired — migrate.
  • Durable Functions for orchestration (fan-out/fan-in, human approval, >10 min); the orchestrator must stay deterministic — no DateTime.Now, no Guid.NewGuid(), no direct I/O.
  • Every Function app still needs a storage account for leases and the host’s own state — give it identity-based access (AzureWebJobsStorage__accountName) rather than a connection string.

Container Apps

az containerapp env create -g rg -n env --location westeurope --enable-workload-profiles
az containerapp create -g rg -n api --environment env \
  --image myacr.azurecr.io/api:1.4.2 --registry-server myacr.azurecr.io --registry-identity system \
  --ingress external --target-port 8080 --min-replicas 0 --max-replicas 30 \
  --scale-rule-name http --scale-rule-type http --scale-rule-http-concurrency 50 \
  --cpu 0.5 --memory 1Gi
az containerapp revision list -g rg -n api -o table
az containerapp ingress traffic set -g rg -n api --revision-weight latest=20 api--rev-7=80
az containerapp job create -g rg -n nightly --environment env --trigger-type Schedule --cron-expression "0 2 * * *"
  • Scaling is KEDA: HTTP concurrency, CPU/memory, or any KEDA scaler (Service Bus queue length, Kafka lag, cron). --min-replicas 0 means cold start; set 1 for latency-sensitive APIs.
  • Revisions are immutable; single-revision mode = rolling replace, multiple-revision mode = weighted traffic split for canaries.
  • Serverless GPUs are GA (per-second billing, scale to zero, NVIDIA NIM microservices supported) — the cheap way to host inference without an AKS GPU pool. Dynamic sessions give Hyper-V-isolated sandboxes for running untrusted or AI-generated code (Python; JavaScript in preview).
  • Workload profiles (Dedicated D/E series) when you need guaranteed compute, larger sizes or a fixed egress footprint inside the same environment.

08AKS & containers

docs: AKS supported versions

AKS supports the current GA minor plus the two before it, 12 months each. As of 2026-09: 1.34 (EOL 2026-11), 1.35 (EOL 2027-03), 1.36 (EOL 2027-06); 1.37 lands ~2026-10. 1.32 and 1.33 are already out of support.

az aks create -g rg -n aks-prod --tier standard \
  --network-plugin azure --network-plugin-mode overlay --network-dataplane cilium \
  --enable-managed-identity --enable-workload-identity --enable-oidc-issuer \
  --enable-azure-rbac --enable-aad --disable-local-accounts \
  --node-count 3 --zones 1 2 3 --enable-cluster-autoscaler --min-count 3 --max-count 20 \
  --auto-upgrade-channel patch --node-os-upgrade-channel NodeImage \
  --enable-azure-monitor-metrics --enable-addons monitoring

az aks get-credentials -g rg -n aks-prod        # never --admin: that is the local account you disabled
kubelogin convert-kubeconfig -l azurecli        # Entra device/CLI token instead of the deprecated legacy mode
az aks nodepool add -g rg --cluster-name aks-prod -n spot --priority Spot \
  --eviction-policy Delete --spot-max-price -1 --node-taints kubernetes.azure.com/scalesetpriority=spot:NoSchedule
az aks upgrade -g rg -n aks-prod --kubernetes-version 1.36.0
az aks nodepool get-rollback-versions -g rg --cluster-name aks-prod -n sys   # CLI 2.88+
az aks command invoke -g rg -n aks-prod -c "kubectl get pods -A"             # private cluster, no jumpbox
Networking choice
Azure CNI Overlay + Cilium is the current default recommendation: pods get an overlay CIDR (no VNet IP exhaustion), nodes get VNet IPs, Cilium gives eBPF dataplane + network policy. kubenet is legacy and being retired; CNI “node subnet” mode burns a VNet IP per pod.
Identity into the cluster
Entra + Azure RBAC for Kubernetes (--enable-azure-rbac) so az role assignment drives kubectl; --disable-local-accounts kills the static admin kubeconfig. Workload identity for pod → Azure calls.
Scaling
cluster autoscaler for nodes, KEDA add-on for event-driven pods, Node Autoprovisioning (Karpenter-based) for SKU-agnostic node supply, --tier standard for the 99.95% control-plane SLA (Free tier has none).
Upgrades
control plane first, then node pools. --auto-upgrade-channel patch plus --node-os-upgrade-channel NodeImage plus a maintenance window and PDBs is the boring, correct setup. A PDB that can never be satisfied blocks drains forever — the most common stuck-upgrade cause.
Registry
az acr build -r myacr -t api:1.4.2 . builds in Azure; attach with az aks update --attach-acr myacr (creates AcrPull). Use az acr import to promote a digest between registries — never rebuild between environments.
Cost control
spot node pools for batch, Standard tier only where the SLA is needed, requests/limits set (unset requests is why the autoscaler does nothing), and az aks nodepool scale --node-count 0 for idle pools.

09Data: Storage, Cosmos DB, Azure SQL

docs: Azure Storage

Storage

az storage account create -g rg -n storders --sku Standard_ZRS --kind StorageV2 \
  --min-tls-version TLS1_2 --allow-blob-public-access false --allow-shared-key-access false \
  --public-network-access Disabled --default-action Deny --https-only true

# the modern way to talk to data: your own Entra identity, no keys
az storage blob upload --account-name storders -c raw -n f.json -f ./f.json --auth-mode login
az storage blob list --account-name storders -c raw --auth-mode login -o table
az storage account generate-sas --account-name storders --permissions rl --expiry 2026-09-09T00:00Z \
  --resource-types co --services b --https-only --auth-mode login --as-user   # user delegation SAS
  • Redundancy: LRS (one DC) → ZRS (3 zones, the sane default) → GRS/GZRS (paired region, async, RPO ~15 min) → RA-GRS/RA-GZRS adds a read-only secondary endpoint. Failover is your call and it is not instant.
  • Access keys are the legacy path: set allowSharedKeyAccess=false and use Entra. Azure CLI 2.92.0 2026-11 flips --access-keys-auth to Disabled by default. Prefer a user delegation SAS (signed by an Entra key, revocable, max 7 days) over an account SAS.
  • Tiers: Hot / Cool (30 d min) / Cold (90 d) / Archive (180 d, rehydrate in hours). Drive them with a lifecycle management policy, not code.
  • Scale target ~20 000 requests/s per account and 500 TB — shard across accounts before you hit it; ServerBusy (503) means back off, the SDK does it for you.
  • Data Lake Gen2 = hierarchical namespace on the same account: real directories, atomic rename, POSIX ACLs. Turn it on at creation or never.

Cosmos DB

az cosmosdb create -g rg -n cos-orders --locations regionName=westeurope failoverPriority=0 isZoneRedundant=true \
  --default-consistency-level Session --enable-automatic-failover true --disable-local-auth true
az cosmosdb sql container create -g rg -a cos-orders -d appdb -n orders \
  --partition-key-path /tenantId --max-throughput 4000        # autoscale RU/s
Partition key
the whole design. High cardinality, even write distribution, present in your hottest query. 20 GB per logical partition (hierarchical keys raise the effective limit). You cannot change it — only migrate.
Consistency
Strong / Bounded staleness / Session (default, right answer 90% of the time) / Consistent prefix / Eventual. Strong forbids multi-region writes across distant regions and doubles RU cost on reads.
RU/s
a 1 KB point read = 1 RU. Autoscale bills max(10% of max, actual) and is right for spiky; manual for steady. 429 = throttled, read x-ms-retry-after-ms; the SDK retries 9 times by default.
Change feed
the built-in outbox/CDC: Functions CosmosDBTrigger or the change-feed processor with a lease container. All-versions-and-deletes mode when you need deletes.
Costs to watch
cross-partition fan-out queries, unbounded indexing (exclude paths you never filter on), and TTL not set on log-like containers.

Azure SQL

  • SQL Database (single / elastic pool / Hyperscale) for new work; Managed Instance when you need SQL Agent, cross-database queries, CLR or a lift-and-shift.
  • Purchasing: vCore (General Purpose / Business Critical / Hyperscale) — DTU is the legacy model still seen in old subscriptions. Serverless auto-pauses for dev/test.
  • Entra-only auth: az sql server ad-only-auth enable; connect with Authentication=Active Directory Default in the connection string and Microsoft.Data.SqlClient (the System.Data.SqlClient package is legacy and has no Entra support worth using).
  • Retry transient errors (40197, 40501, 40613, 49918…) — EnableRetryOnFailure() in EF Core, or ConnectRetryCount. A cloud database will drop your connection during a maintenance failover.
  • Business Critical gives a free read replica (ApplicationIntent=ReadOnly); Hyperscale scales storage to 128 TB with near-instant restore.

// identity-based, no connection string, one client registered as a singleton
builder.Services.AddSingleton(new ServiceBusClient(
    "sb-orders.servicebus.windows.net", new DefaultAzureCredential()));

await using var processor = client.CreateProcessor("orders", "billing",
    new ServiceBusProcessorOptions { MaxConcurrentCalls = 8, PrefetchCount = 32, AutoCompleteMessages = false });

processor.ProcessMessageAsync += async args =>
{
    try   { await Handle(args.Message, args.CancellationToken); await args.CompleteMessageAsync(args.Message); }
    catch (PoisonException) { await args.DeadLetterMessageAsync(args.Message, "poison", "schema mismatch"); }
    // no Abandon on transient failure: let the lock expire so delivery is retried with backoff
};
processor.ProcessErrorAsync += e => { log.LogError(e.Exception, "bus {Source}", e.ErrorSource); return Task.CompletedTask; };
await processor.StartProcessingAsync();
  • Sessions are the only way to get FIFO per key on Service Bus; they also serialise a key’s processing, so a slow message blocks that session only.
  • Peek-lock (default) vs receive-and-delete: use peek-lock, renew the lock for long work (MaxAutoLockRenewalDuration), and make handlers idempotent — delivery is at least once.
  • Dead-letter reasons to check first: MaxDeliveryCountExceeded (default 10), TTLExpiredException, HeaderSizeExceeded. Always ship a DLQ alarm and a replay path.
  • Event Hubs partition count is fixed at creation for Standard (changeable on Premium/Dedicated); consumers > partitions means idle consumers. Checkpoints live in a blob container.
  • Event Grid delivers CloudEvents 1.0 schema for new topics; the legacy “Event Grid schema” is still what most built-in Azure system topics emit.
  • Service Bus control-plane API versions 2015/2017-era are being retired — if a script pins an old api-version for namespace management, update it.

Private Endpoint vs Service Endpoint
PE = a private IP in your subnet for one PaaS resource, works across peering and on-prem, requires a private DNS zone. Service Endpoint = the traffic still goes to the public IP but is tagged with the subnet identity; cheaper, VNet-local only, no DNS change. PE is the modern default.
The PE failure mode
99% of “private endpoint doesn’t work” is DNS: the client still resolves the public IP. Check with nslookup kv.vault.azure.net — it must return the 10.x address via the privatelink.* zone linked to the client’s VNet.
Egress
default outbound access for new VMs is retired — give every subnet an explicit path: NAT Gateway (simplest, SNAT-port-safe), Standard LB outbound rule, or Azure Firewall. SNAT port exhaustion is the classic “works at 10 rps, fails at 100”.
L7 in front
Front Door (global anycast, WAF, caching, TLS at edge) for internet-facing multi-region; Application Gateway v2 (regional, WAF, mTLS, private) inside a region; both, chained, is a common enterprise shape. Traffic Manager is DNS-only failover — still useful for non-HTTP.
Peering vs hub-spoke
peering is non-transitive: spoke↔spoke needs a hub NVA/Firewall with UDRs, or Virtual WAN. Overlapping address spaces cannot peer — plan CIDR once, centrally.
NSG order
lowest priority number wins; default rules allow VNet-in/out and deny Internet-in. Service Tags (AzureKeyVault, Storage.westeurope, AzureMonitor) beat hard-coded IP lists. az network watcher test-ip-flow tells you which rule blocked you.
Retired basics
Basic Load Balancer and Basic (ARM) public IPs retired 2025-09-30; from 2026-03-31 remaining Basic public IPs are billed at Standard rates. Standard SKU is zone-redundant and secure-by-default (deny inbound unless an NSG allows).

The credential chain
DefaultAzureCredential tries, in order: Environment → Workload Identity → Managed Identity → Visual Studio → Azure CLI → Azure PowerShell → azd → interactive browser. SharedTokenCacheCredential has been dropped from the chain. In production, prefer an explicit ManagedIdentityCredential or ChainedTokenCredential — deterministic, and no 30-second probe when IMDS is absent.
AZURE_TOKEN_CREDENTIALS
set it to dev, prod or a single credential name to prune the chain without a code change; 1.21 also lets you name a custom environment variable in the constructor.
Key Vault
az keyvault create -g rg -n kv --enable-rbac-authorization true --enable-purge-protection true. RBAC (Key Vault Secrets User) has replaced access policies — policies are the legacy model you will still find. Soft delete is mandatory; purge protection blocks even a purge for the retention period.
Key Vault references
App Service / Functions / Container Apps resolve @Microsoft.KeyVault(SecretUri=…) at startup with the app’s managed identity — no SDK call, but a rotation needs a restart unless you read via the SDK.
App Configuration
the place for feature flags and non-secret config with labels per environment; use a sentinel key + refreshAll so one write reloads everything. Secrets stay in Key Vault, referenced.
Rate limits & retries
Key Vault throttles at ~2 000 transactions / 10 s per vault: cache secrets in memory, never fetch per request. All Azure SDK clients retry with exponential backoff and jitter by default; make them singletons or you leak sockets and re-fetch tokens.
Deprecated packages
Microsoft.Azure.KeyVault, Microsoft.Azure.Storage.*, WindowsAzure.Storage, Microsoft.Azure.ServiceBus, Microsoft.Azure.DocumentDB, Microsoft.IdentityModel.Clients.ActiveDirectory (ADAL, retired 2022) — all replaced by Azure.* track-2 packages and MSAL. Finding one in a repo is a migration ticket.

KQL operators worth memorising
where project extend summarize … by bin(TimeGenerated, 5m) join kind=leftouter make-series parse mv-expand materialize() render timechart. Filter first, then project — it is a columnar store.
Diagnostic settings
nothing is logged until you say so: az monitor diagnostic-settings create --resource $ID -n toLaw --workspace $LAW --logs '[{"categoryGroup":"allLogs","enabled":true}]' --metrics '[{"category":"AllMetrics","enabled":true}]'. Enforce it fleet-wide with a deployIfNotExists policy.
Alerts
metric alerts (cheap, near real-time) for platform signals; log/scheduled query alerts for business signals; every alert gets an action group and a runbook link. az monitor metrics alert create --condition "avg Percentage CPU > 80" --window-size 5m --evaluation-frequency 1m.
Cost control
ingestion is the bill. Use Basic or Auxiliary table plans for chatty, rarely-queried logs, a commitment tier above ~100 GB/day, transformations in the DCR to drop noisy columns, and per-table retention. Usage | summarize sum(Quantity) by DataType finds the offender.
Agents
Azure Monitor Agent + Data Collection Rules is the only supported agent; the Log Analytics agent (MMA/OMS) was retired 2024-08-31. Managed Prometheus + managed Grafana for container metrics; enable control-plane metrics with az aks update --enable-control-plane-metrics CLI 2.88.
Sampling
adaptive sampling is on by default in App Insights — remember it when a count looks wrong; itemCount is the multiplier, and summarize sum(itemCount) is the honest count.

14Resilience, cost & limits

docs: Azure reliability
Composite SLA
serial dependencies multiply: 99.95% × 99.99% × 99.99% ≈ 99.93% ≈ 6 h/year. Adding a component lowers availability unless you add redundancy with it. Know this number for your own system — it is a standard principal-level question.
Zones vs regions
zone-redundant deployment is cheap and covers the common failure (one datacentre); multi-region is expensive and only pays off with an actual data strategy (async replica + accepted RPO, or active-active with conflict handling). Choose per RTO/RPO, not per ambition.
Paired vs flexible regions
classic region pairs give sequential updates and geo-replication targets; newer regions ship without a pair and rely on zones. Check before you promise a DR region.
Retry
exponential backoff + jitter, bounded; circuit breaker around the dependency; timeouts everywhere (HttpClient default is 100 s — far too long). In .NET, Microsoft.Extensions.Http.Resilience (AddStandardResilienceHandler()) is the current answer; Polly v7 pipelines built by hand are the legacy shape.
Cost levers, biggest first
right-size and shut down non-prod on a schedule → reservations (1/3 yr, ~40–60%) or a savings plan for compute (flexible across services/regions) → Azure Hybrid Benefit for Windows/SQL licences → spot for interruptible → storage tiering → log ingestion. Egress and cross-zone traffic are the invisible ones.
Seeing the money
az consumption usage list --start-date 2026-09-01 --end-date 2026-09-08 --query "[].{r:instanceName, c:pretaxCost}" -o table; Cost Management exports to storage + a budget with an action group beats a monthly surprise. Tag costCenter from day one — retro-tagging never happens.
Limits you will actually hit
800 deployments per RG history (they auto-prune now, but a tight loop still errors), 250 resource groups’ worth of subscription-level assignments, 4 000 role assignments/sub, 1 000 VMs per VMSS, 65 000 ARM writes/hour/sub, 20 000 storage requests/s/account, 500 Key Vault ops/s. Ask for a quota increase before the launch, not during.

15Gotchas, one line each

docs: common deployment errors
  • Incremental is not idempotent-safe: a property you removed from the template stays on the resource; only Complete mode or a deployment stack removes it.
  • Role assignment propagation (up to ~5 min) makes deploy-then-use pipelines flaky — retry, or split provisioning from first use.
  • Control plane ≠ data plane: Contributor on a storage account gives you no blob access once shared keys are off.
  • Key Vault soft delete means a redeploy under the same name fails until az keyvault purge — and with purge protection on, you simply wait 90 days.
  • Slot settings: app settings not marked as slot settings follow the swap; that is how staging ends up writing to prod.
  • Always On off on a non-Consumption App Service means the app unloads after 20 idle minutes and the next request eats a cold start.
  • Private endpoint but public DNS: if nslookup returns a public IP, the private DNS zone is not linked to the client’s VNet.
  • SNAT port exhaustion looks like random timeouts under load; the fix is a NAT Gateway and reusing HttpClient.
  • VNet peering is not transitive — spoke-to-spoke needs the hub, plus UDRs, plus firewall rules.
  • Cosmos 429s are normal, not an outage: read x-ms-retry-after-ms, and check for a cross-partition query before adding RU/s.
  • The partition key is permanent. Changing it means a new container and a migration.
  • App Insights adaptive sampling silently divides your counts; use sum(itemCount).
  • Nothing is logged by default — a resource with no diagnostic setting produces no platform logs, and you find out during the incident.
  • Log Analytics ingestion is the bill, not retention; a chatty debug logger can outspend the compute it monitors.
  • Managed identity with several UAMIs attached fails ambiguously unless you set the client ID explicitly.
  • IMDS is not reachable from your laptop — local dev uses the CLI/VS credential in the chain; that is the whole point of DefaultAzureCredential.
  • Availability zone numbers differ per subscription; do not compare “zone 1” across subscriptions when spreading resources.
  • Resource moves lock both resource groups and silently exclude several resource types — redeploy instead.
  • ARM write MFA now breaks unattended scripts running under a human’s account; move them to a service principal or managed identity.
  • ReadOnly locks break listing storage keys and restarting apps, because those are POST operations.
  • Tags are not inherited; a cost report grouped by tag is wrong until a modify policy fills them in.
  • Soft-deleted App Service names and globally unique names stay reserved — naming collisions across environments are a design smell.
