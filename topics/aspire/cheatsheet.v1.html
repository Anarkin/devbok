.NET Aspire · cheatsheet · version 1 · 2026-09-08

.NET Aspire

cheatsheet · 13.5.3 · released 2026-08-25

Reference card for Aspire — the app model, CLI, integrations, publish/deploy targets and the modern-vs-legacy deltas — current to 13.5.3 (patch, 2026-08-25) on the 13.5 line (2026-08-18). "Aspire" here is the Microsoft orchestration platform formerly branded ".NET Aspire"; it dropped the ".NET" prefix in 13.0 and is now polyglot, so C#, TypeScript, JavaScript, Python and Go all appear. Version labels mark where a construct became stable, default or obsolete, because Microsoft supports only the newest Aspire release — 13.4 was supported for barely ten weeks.

13.5.3 2026-08-25 minor line 13.5 · 2026-08-18 requires .NET 10 SDK apphost targets net10.0 latest release only is supported

01Bootstrap & solution shape

One AppHost orchestrates everything; every service references ServiceDefaults. Since 13.0 the AppHost targets net10.0 and the SDK is pinned inline.

New solution, interactive
aspire new — templates: aspire-starter, aspire-apphost, aspire-apphost-singlefile, aspire-ts-cs-starter, aspire-py-starter
Add Aspire to an existing repo
aspire init — detects projects, writes AppHost + aspire.config.json; runs the aspireify agent skill (13.3+)
AppHost csproj (13.0+)
<Project Sdk="Aspire.AppHost.Sdk/13.5.3"> — single rooted SDK; no separate Aspire.Hosting.AppHost PackageReference
Single-file AppHost (13.0+)
apphost.cs with #:sdk / #:package directives; needs .NET 10 SDK
Project-scoped config (13.2+)
aspire.config.json at the repo root — SDK version, appHost.path, launch profiles, package pins
Run + dashboard
aspire run (dashboard auto-opens); aspire start to detach, aspire stop, aspire ps
Add an integration
aspire add redis, aspire add azure-storage — resolves the right package + version for your SDK line
Bump every Aspire package
aspire update; aspire update --self updates the CLI itself (13.0+)
// apphost.cs (single-file) or AppHost/Program.cs
var builder = DistributedApplication.CreateBuilder(args);

var cache = builder.AddRedis("cache");
var db    = builder.AddPostgres("pg").WithPgAdmin().AddDatabase("appdb");

var api = builder.AddProject<Projects.Api>("api")
                 .WithReference(cache).WaitFor(cache)
                 .WithReference(db).WaitFor(db);

builder.AddProject<Projects.Web>("web")
       .WithReference(api).WaitFor(api)
       .WithExternalHttpEndpoints();

builder.Build().Run();
// ServiceDefaults/Extensions.cs is referenced by every service project
builder.AddServiceDefaults();   // OTel + health checks + service discovery + resilient HttpClient
var app = builder.Build();
app.MapDefaultEndpoints();      // /health and /alive, development only by default

02App model: resources

Three primitives — project, container, executable — plus parameters and connection strings. Everything else is an extension method on IResourceBuilder<T>.

.NET project
builder.AddProject<Projects.Api>("api") — generated Projects.* type; name is the service-discovery key
Container
builder.AddContainer("mailpit", "axllent/mailpit")
Local executable
builder.AddExecutable("worker", "./tool", workingDirectory: ".", "--flag")
C# file-based app (13.0+, exp.)
builder.AddCSharpApp("tool", "../tools/tool.cs")
Dockerfile in-repo
builder.AddDockerfile("svc", "./src/svc"); .WithBuildArg(...), .WithBuildSecret(...) renamed in 13.2
Scale out locally
.WithReplicas(3) — the reverse proxy load-balances the endpoint
Keep container between runs
.WithLifetime(ContainerLifetime.Persistent) — survives AppHost restart, big win on cold-start time
Pin an image tag
.WithImageTag("18.3"), .WithImageRegistry("mcr.microsoft.com"), .WithImage("postgres")
State that must survive
.WithDataVolume("pgdata") (named volume) or .WithDataBindMount("./data") (host path)
Seed / config files into a container
.WithContainerFiles("/docker-entrypoint-initdb.d", [ ... ])
Environment & args
.WithEnvironment("KEY", value), .WithArgs("--verbose"), .WithEnvironment(ctx => ...) for late binding
Hide plumbing from the dashboard
.WithParentRelationship(db), .ExcludeFromManifest()
Custom dashboard command
.WithCommand("seed", "Seed data", ctx => ...); user-supplied CommandOptions.Arguments 13.5
Interactive terminal (13.5, exp.)
.WithTerminal() — opens a live PTY for the resource in the dashboard
Health gate
.WithHttpHealthCheck("/health") — drives WaitFor and the dashboard's Running/Healthy split

03References, waiting, endpoints

A reference injects config; a wait orders startup. They are independent — forgetting WaitFor is the classic flaky-first-run bug.

Inject connection info
.WithReference(db) — writes ConnectionStrings__appdb into the consumer
Inject a service URL
.WithReference(api) — writes services__api__https__0; call it as https://api
Order startup
.WaitFor(db) (healthy) and .WaitForCompletion(migrator) (exit code 0) — for one-shot migration jobs
Wait with a specific exit code
.WaitForCompletion(seed, exitCode: 0)
Reference a specific endpoint
.WithReference(api.GetEndpoint("grpc"))
Extra endpoint
.WithHttpEndpoint(port: 5100, targetPort: 8080, name: "admin"), .WithHttpsEndpoint(...), .WithEndpoint(scheme: "tcp", ...)
Publish to the internet
.WithExternalHttpEndpoints() — only these get public ingress at deploy time
Share a dev tunnel
builder.AddDevTunnel("tunnel").WithReference(web) — stable since 13.1
HTTPS for a project (13.5)
.WithHttpsDeveloperCertificate() / .WithHttpsCertificate(cert)
Reverse proxy / gateway
builder.AddYarp("gw").WithConfiguration(c => c.AddRoute("/api/{**c}", api))
Raw connection string
builder.AddConnectionString("legacy") — use instead of PublishAsConnectionString, obsolete in 13.5
Bypass the proxy
.WithEndpoint("http", e => e.IsProxied = false) — port allocation now happens later breaking in 13.5
Service discovery changed in 13.2: the injected variable is keyed by endpoint scheme, not endpoint name — services__api__https__0, not services__api__myendpoint__0. Code that parsed the old shape by hand breaks silently.

04Parameters, secrets, config

Parameters are the deploy-time inputs of the app model. Secrets stay in user-secrets locally and become key-vault or environment references when published.

Declare a parameter
var pw = builder.AddParameter("db-password", secret: true);
Local value
user-secrets key Parameters:db-password, or aspire secret set Parameters:db-password ...
Prompted at deploy
unset secret parameters are prompted by aspire deploy via the Interaction Service
Generate one
builder.AddParameter("pw", () => Guid.NewGuid().ToString(), secret: true); .WithGeneratedPassword() on supported resources
Use it
builder.AddPostgres("pg", password: pw) or .WithEnvironment("PW", pw)
Ask the developer at runtime
IInteractionService.PromptInputAsync(...); InputType.File uploads with a progress dialog 13.5
CLI config
aspire config list|get|set|delete — e.g. aspire config set features.deployCommandEnabled true
Allow plain HTTP
ASPIRE_ALLOW_UNSECURED_TRANSPORT=true (CI, WSL, containers without a dev cert)
Use Podman
ASPIRE_CONTAINER_RUNTIME=podman
Dashboard OTLP endpoints
ASPIRE_DASHBOARD_OTLP_ENDPOINT_URL (gRPC), ASPIRE_DASHBOARD_OTLP_HTTP_ENDPOINT_URL
Environment name
ASPIRE_ENVIRONMENT, else DOTNET_ENVIRONMENT/ASPNETCORE_ENVIRONMENT
Dev certs
aspire certs — 13.0 trusts the dev cert across languages automatically

05Integrations: hosting + client

06Service defaults & telemetry

ServiceDefaults is generated source you own, not a package — edit it. Aspire adds no runtime dependency to your services beyond OpenTelemetry, service discovery and resilience.

What AddServiceDefaults() wires
OTel traces/metrics/logs + OTLP exporter · AddServiceDiscovery() · HttpClient defaults with AddStandardResilienceHandler() · default health checks
What MapDefaultEndpoints() maps
/health (all checks) and /alive (checks tagged "live") — guarded to Development by default; open it deliberately for prod probes
Tag a liveness check
.AddCheck("self", () => HealthCheckResult.Healthy(), ["live"])
Where telemetry goes
OTEL_EXPORTER_OTLP_ENDPOINT is injected by the AppHost and points at the dashboard; in production point it at your collector
Add a meter / source
.WithMetrics(m => m.AddMeter("MyApp")), .WithTracing(t => t.AddSource("MyApp")) in ConfigureOpenTelemetry
Typed HttpClient to a service
builder.Services.AddHttpClient<ApiClient>(c => c.BaseAddress = new("https+http://api"));
Dashboard alone (13.3+)
aspire dashboard — runs standalone as an OTLP sink for anything, no AppHost needed
Telemetry out of the CLI
aspire otel --search "status:500", aspire logs --search error, aspire export
Scheme fallback: https+http://api resolves HTTPS first and falls back to HTTP — the right default for local dev where a container may only expose HTTP.

07Polyglot: TS, JS, Python, Go

13.0 dropped the ".NET" from the name for a reason. The AppHost itself can now be TypeScript (GA in 13.4), and JS/Python/Go apps are first-class resources, not shelled-out executables.

TypeScript AppHost (GA 13.4)
createBuilder() from @aspire/hosting; talks to the host over JSON-RPC; generated SDKs land in .aspire/modules/ moved in 13.4
JavaScript app
builder.AddJavaScriptApp("web", "../web", "dev") — package Aspire.Hosting.JavaScript renamed in 13.0 from Aspire.Hosting.NodeJs
Framework helpers
AddViteApp, AddNextJsApp 13.3, AddBunApp 13.4; npm, pnpm, Yarn and Bun all detected
JS publish modes (13.3)
PublishAsStaticWebsite(), PublishAsNodeServer(), PublishAsPackageScript() renamed in 13.4 from PublishAsNpmPackageScript
Python
builder.AddPythonApp("api", "../api", "main.py"); uvicorn support built in; aspire new aspire-py-starter
Go (13.4)
builder.AddGoApp("svc", "../svc") — package Aspire.Hosting.Go
Blazor WASM (13.4, preview)
builder.AddBlazorWasmProject<Projects.Client>("client") with gateway APIs
Dependency install
13.0 auto-installs Python/JS dependencies by default before the app starts
// aspire.ts — TypeScript AppHost, GA in 13.4
import { createBuilder } from "@aspire/hosting";

const builder = createBuilder();
const cache = builder.addRedis("cache");
const api = builder.addProject("api", "../Api/Api.csproj").withReference(cache).waitFor(cache);
builder.addViteApp("web", "../web").withReference(api).withExternalHttpEndpoints();
await builder.build().run();

09Publish & deploy

Compute environments are the deploy target in the app model. aspire publish emits artifacts; aspire deploy provisions and applies. The old manifest.json + azd path is a deprecated compatibility shim.

Azure Container Apps
builder.AddAzureContainerAppEnvironment("env")
Azure App Service
builder.AddAzureAppServiceEnvironment("env")
Docker Compose
builder.AddDockerComposeEnvironment("compose") — stable in 13.2; Podman supported 13.3
Kubernetes / AKS
builder.AddKubernetesEnvironment("k8s") with a Helm engine 13.3, first-class in 13.3; AddAzureKubernetesEnvironment for AKS
Pick a target per resource
.WithComputeEnvironment(env) — graduated from experimental in 13.0; required once two environments exist
Helm config (13.4)
.WithHelm(h => ...) consolidated; external chart APIs; K8s manifest resources
K8s storage (13.5)
AddPersistentVolume(...) for PV/PVC generation
Ingress / routing (13.3+)
Ingress and Gateway API resources; cert-manager and Azure Application Gateway for Containers 13.4; WithPath() renamed in 13.4 from WithRoute()
Reuse existing Azure resources
.AsExisting(name, rg); cross-scope AsExistingInResourceGroup / InSubscription / InTenant 13.5
Custom infra
.ConfigureInfrastructure(infra => ...) to edit the generated Bicep/CDK before emit
Pipeline steps
aspire do build, aspire do deploy — the do pipeline system 13.0, experimental
Tear down
aspire destroy --yes — removes what was provisioned, across Azure, K8s and Compose
Identity default (13.0): in Azure deployments Aspire narrows DefaultAzureCredential to ManagedIdentityCredential. Deployed code that silently relied on a developer credential chain now fails fast — which is the point.

10Eventing, custom resources, tests

Lifecycle hooks are gone; eventing subscribers replace them. Integration tests boot the real app model in-process.

Subscribe to a lifecycle event
builder.Eventing.Subscribe<BeforeStartEvent>((e, ct) => ...)
Per-resource events
builder.Eventing.Subscribe<ResourceReadyEvent>(db.Resource, (e, ct) => ...); also OnResourceReady, OnBeforeResourceStarted, OnConnectionStringAvailable, OnInitializeResource
Discoverable subscriber
implement IDistributedApplicationEventingSubscriber — replaces IDistributedApplicationLifecycleHook, deprecated in 13.0
Custom resource
class MyResource(string name) : Resource(name), IResourceWithConnectionString + an Add* extension method
Push state to the dashboard
IResourceNotificationService.PublishUpdateAsync(res, s => s with { State = KnownResourceStates.Running })
Structured command results (13.3)
resource commands return structured output surfaced in the dashboard, CLI and MCP tools alike
Integration test host
await DistributedApplicationTestingBuilder.CreateAsync<Projects.AppHost>() — package Aspire.Hosting.Testing
Client for a resource
app.CreateHttpClient("api"); await app.GetConnectionStringAsync("appdb")
Wait in a test
await app.ResourceNotifications.WaitForResourceHealthyAsync("api", cts.Token)
[Fact]
public async Task ApiIsHealthy()
{
    var builder = await DistributedApplicationTestingBuilder.CreateAsync<Projects.AppHost>();
    builder.Services.ConfigureHttpClientDefaults(h => h.AddStandardResilienceHandler());

    await using var app = await builder.BuildAsync();
    await app.StartAsync();
    await app.ResourceNotifications.WaitForResourceHealthyAsync("api");

    var response = await app.CreateHttpClient("api").GetAsync("/health");
    Assert.Equal(HttpStatusCode.OK, response.StatusCode);
}

11Gotchas & pitfalls

  • Only the newest release is supported. Aspire 13.4 shipped 2026-06-01 and left support on 2026-08-18 — a ~10-week window. Budget a standing upgrade cadence, not an annual one.
  • WithReference is not WaitFor. A reference injects config; without WaitFor the consumer starts against a database that is not accepting connections yet.
  • Migrations need WaitForCompletion, not WaitFor — WaitFor waits for healthy, which a one-shot job never becomes.
  • PostgreSQL image jumped to 18.3 in 13.4. Existing volumes written by PG 17 will not mount; pin .WithImageTag("17") or re-seed.
  • Service discovery keys by scheme since 13.2 (services__api__https__0). Hand-rolled parsing of the old name-keyed shape breaks without an error.
  • PublishAsConnectionString is obsolete (13.5) — use AddConnectionString. ServiceProvider on hosting contexts is now Services.
  • Aspire is dev-time orchestration, not a runtime. Nothing named "Aspire" runs in production — the AppHost and dashboard stay on the dev box or CI.
  • Deployment manifest + azd up is legacy. The manifest format is a frozen compatibility shim; new Azure features land only in aspire deploy.
  • Containers restart every run unless you set .WithLifetime(ContainerLifetime.Persistent); without it, every aspire run pays a cold start and loses non-volume state.
  • Dev cert on Linux/WSL/CI is the most common first-run failure: run aspire doctor, then aspire certs, or set ASPIRE_ALLOW_UNSECURED_TRANSPORT=true.
  • The dashboard is not hardened for the internet. If you host it standalone, front it with auth; never set ASPIRE_DASHBOARD_UNSECURED_ALLOW_ANONYMOUS outside a trusted network.
  • Two compute environments without WithComputeEnvironment means resources silently fail to get an image built for the target you expected.
  • Third-party container images are your risk. Microsoft's support policy explicitly excludes the images behind the Add* APIs — scan and pin them yourself.
  • Dashboard AI Assistant and the dashboard MCP server were removed (13.5 and 13.3). Agent access now goes through aspire agent init and aspire mcp.
