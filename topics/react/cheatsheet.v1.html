React

cheatsheet · React 19.2.8 · released 2026-07-21

The React surface reached for daily — JSX, the whole hook set, Suspense and use(), transitions and <Activity>, Actions and form hooks, Server Components and Server Functions, the react-dom APIs, and the compiler/lint toolchain — each row labelled with the version where it became true, plus a modern-vs-legacy table and a timeline. It reflects the 19.2 line: 19.2.0 on 2025-10-01, current patch 19.2.8 on 2026-07-21, with useEffectEvent, <Activity>, cacheSignal and partial pre-rendering stable, React Compiler 1.0 shipped, and <ViewTransition> still canary-only. "React" here is the web library on react/react-dom; React Native shares the reconciler and hooks but has its own release line (0.83 tracks React 19.2).

01JSX & components

docs: writing markup with JSX
Component
function Row({ item, onPick }) { return <li onClick={() => onPick(item.id)}>{item.name}</li>; } — a plain function returning JSX; the name must be capitalised or JSX emits a DOM tag
Fragment
<>…</>, keyed form <Fragment key={id}>…</Fragment>
Lists
{items.map(i => <Row key={i.id} item={i} />)} — key must be stable and data-derived; index keys corrupt state on reorder
Conditionals
{open && <Panel />} · {n ? <A /> : <B />} — {count && …} renders a literal 0; write count > 0 &&
Props spread & children
<Input {...rest} /> · function Card({ children, ...rest }) · render prop <List row={(i) => …} />
ref as a prop
function Input({ ref, ...p }) { return <input ref={ref} {...p} />; } 19.0 — forwardRef is no longer needed; it still works but is slated for deprecation
Context provider
<ThemeContext value={theme}>…</ThemeContext> 19.0 — <Context.Provider> still works, deprecated in a future major
Attribute names
className, htmlFor, onChange (fires per keystroke), defaultValue for uncontrolled; style={{ marginTop: 8 }} camelCase, px by default
Custom elements
19.0 full custom-element support — unknown lowercase tags take strings as attributes and objects/functions as properties
Types (TS)
type Props = { items: Item[]; onPick?: (id: string) => void }; — annotate the parameter, not React.FC; ReactNode for children, ComponentProps<'button'> to inherit DOM props
// The whole component contract in one snippet.
export default function Cart({ items, ref }) {          // ref is a prop (19.0)
  const total = items.reduce((s, i) => s + i.price, 0); // derive, do not store
  return (
    <section ref={ref}>
      <h2>Cart ({items.length})</h2>
      {items.length > 0
        ? <ul>{items.map(i => <Row key={i.id} item={i} />)}</ul>
        : <p>Empty</p>}
      <output>{total.toFixed(2)}</output>
    </section>
  );
}

Rules of React. Render must be pure: no mutation of props, state or module scope, no side effects, no conditional hook calls. React Compiler both relies on these rules and enforces them at lint time, so violations that used to be invisible now fail the build.

02Hooks: state, memo, refs

docs: built-in hooks
useState
const [n, setN] = useState(0) · updater form setN(v => v + 1) for consecutive updates · lazy init useState(() => parse(json)) runs once
useReducer
const [state, dispatch] = useReducer(reducer, init) — for state with several interdependent fields or an event vocabulary; the reducer is testable without React
Derived state
Compute during render: const visible = items.filter(f) — never mirror props into state; to reset state on a prop change use key, not an effect
Adjust state on prop change
if (item !== prev) { setPrev(item); setSel(null); } during render — React re-runs the component immediately, before paint; rare but legal
useMemo / useCallback
useMemo(() => sort(rows), [rows]) · useCallback(fn, deps) — with React Compiler on, mostly unnecessary; keep only for genuinely expensive work or identity a third party depends on
memo
const Row = memo(function Row(p) {…}) — shallow prop compare; useless if the parent passes fresh object/array/closure literals
useRef
const el = useRef(null) — mutable box, writes never re-render. Callback refs may return a cleanup 19.0: ref={n => { obs.observe(n); return () => obs.unobserve(n); }}
useContext
const theme = useContext(ThemeContext) — every consumer re-renders when the value identity changes; split the context or memoise the value
useSyncExternalStore
useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot) 18.0 — tearing-free reads from a non-React store; what Redux and Zustand use internally
useId
const id = useId() — SSR-safe ids for htmlFor/aria-*; default prefix _r_ 19.2 (was «r» in 19.1, :r: in 19.0). Never a list key
useImperativeHandle
useImperativeHandle(ref, () => ({ focus, scrollToRow }), []) — expose a narrow API instead of a raw DOM node
useDebugValue
useDebugValue(online ? 'online' : 'offline') — labels a custom hook in DevTools
// Reducer + external store: the two hooks that scale past a handful of useStates.
const [state, dispatch] = useReducer(cartReducer, { lines: [], coupon: null });

const isOnline = useSyncExternalStore(
  (cb) => {
    window.addEventListener('online', cb); window.addEventListener('offline', cb);
    return () => { window.removeEventListener('online', cb); window.removeEventListener('offline', cb); };
  },
  () => navigator.onLine,   // client snapshot — must be cached, not a fresh object
  () => true                // server snapshot, required under SSR
);

03Effects & useEffectEvent

docs: useEffectEvent
useEffect
useEffect(() => { const s = connect(url); return () => s.close(); }, [url]) — only for synchronising with systems outside React. Runs after paint; anything that subscribes must return a cleanup
useEffectEvent
const onMsg = useEffectEvent(m => log(m, theme)); 19.2 — always sees the latest props/state, is not a dependency, and the linter knows to skip it. Retires the "ref holding the latest callback" workaround
useLayoutEffect
Runs synchronously before paint — measuring and repositioning (tooltips, popovers) only; it blocks the frame and does not run on the server
useInsertionEffect
Fires before layout effects — for CSS-in-JS libraries injecting <style>; application code should never need it
Not an effect
Transforming data → compute in render · responding to an event → the handler · resetting on a prop change → key · app init once → module scope
Dependencies
Every reactive value read inside must be listed — never silence the rule; remove the dependency instead (Effect Event, ref, or hoist out of the component)
Strict Mode
Dev double-invokes render, effects and state updaters; ref callbacks too 19.0 — an effect that breaks on mount → unmount → mount is missing cleanup
Cancelling fetches
const c = new AbortController(); fetch(u, { signal: c.signal }); return () => c.abort(); — or drop effect-fetching entirely for a framework loader, RSC, or a query library
// Modern (19.2): the effect depends on roomId alone; a theme change no longer reconnects.
function Chat({ roomId, theme }) {
  const onConnected = useEffectEvent(() => showToast('Connected!', theme));

  useEffect(() => {
    const conn = createConnection(roomId);
    conn.on('connected', onConnected);
    conn.connect();
    return () => conn.disconnect();
  }, [roomId]);                        // ✅ theme is not a dependency
}

// Legacy still in codebases: the ref-latest dance, or theme in deps causing reconnect storms.
const themeRef = useRef(theme);
useEffect(() => { themeRef.current = theme; });

04Suspense, use() & errors

docs: Suspense
<Suspense>
<Suspense fallback={<Skeleton />}><Rows /></Suspense> — the boundary for anything that suspends: lazy, use(), RSC streaming
use()
const data = use(promise) / const t = use(ThemeContext) 19.0 — not a hook: may be called conditionally and in loops. The promise must be stable — from a framework, an RSC, or a cache — never created during render
lazy
const Chart = lazy(() => import('./Chart')) — declare at module scope and pair with a Suspense boundary
Error boundary
Class with static getDerivedStateFromError + componentDidCatch — still the only built-in mechanism (react-error-boundary is the usual wrapper). Does not catch event-handler or async errors
Root error hooks
createRoot(el, { onUncaughtError, onCaughtError, onRecoverableError }) 19.0 — one place to pipe React errors into telemetry
Owner Stacks
captureOwnerStack() 19.1 — dev-only; the stack of components that rendered the element, far more useful in reports than the JS stack
Hydration errors
19.0 one message with a server-vs-client diff — usual causes: Date.now(), window, locale formatting, extensions injecting nodes
SSR reveal batching
19.2 streaming SSR briefly batches Suspense reveals — fewer layout pops, and server reveal order now matches the client
Sibling pre-warming
19.0 when one child suspends, siblings still begin their work — removes a class of accidental request waterfalls
// use() reads a promise created by the server or a loader, never by this render.
function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);        // suspends until it resolves
  return comments.map(c => <p key={c.id}>{c.body}</p>);
}

<ErrorBoundary fallback={<Failed />}>
  <Suspense fallback={<Skeleton rows={5} />}>
    <Comments commentsPromise={commentsPromise} />
  </Suspense>
</ErrorBoundary>

Never use(fetch(...)) inline. A promise created during render is a new promise on every render, so the boundary re-suspends forever. Hoist it into a loader, a server component, or cache().

05Transitions & Activity

docs: Activity
useTransition
const [isPending, startTransition] = useTransition() 18.0 — marks an update interruptible so typing stays responsive while a heavy list re-renders
Async transitions
startTransition(async () => { await save(f); setDone(true); }) 19.0 — isPending stays true across the await; this is what Actions are built on
startTransition (import)
import { startTransition } from 'react' — same semantics without the pending flag, usable outside components
useDeferredValue
const q = useDeferredValue(query), with an initial value useDeferredValue(query, '') 19.0 — render the expensive subtree from the lagging copy
<Activity>
<Activity mode={visible ? 'visible' : 'hidden'}><Tab /></Activity> 19.2 — hidden keeps state and DOM, unmounts effects, and defers updates until React is idle. Pre-render the likely next screen; keep scroll and input state on back
<ViewTransition>
<ViewTransition>…</ViewTransition> + addTransitionType() — wraps the browser View Transition API; canary/experimental only as of 19.2, so npm i react@canary, not production-blessed
Performance Tracks
19.2 Chrome DevTools performance profiles gain Scheduler and Components tracks — shows work by priority and which component blocked the frame; the first-stop profiling tool now
Priority model
Sync (discrete input) > default > transition > Activity-hidden pre-render — transitions never block a keystroke; hidden Activity work is the lowest of all
// Activity: keep the previous tab alive instead of unmounting it.
<Activity mode={tab === 'search' ? 'visible' : 'hidden'}>
  <SearchTab />                {/* state, scroll and inputs survive; effects are unmounted */}
</Activity>

// Transitions: urgent input, non-urgent list.
const [isPending, startTransition] = useTransition();
function onChange(e) {
  setQuery(e.target.value);                        // urgent — the input updates now
  startTransition(() => setResults(search(e.target.value))); // interruptible
}

Activity vs conditional rendering vs CSS. {show && <Tab />} throws state away; display: none keeps state and keeps effects (sockets, timers) running. <Activity mode="hidden"> is the only option that keeps state while releasing effects.

06Forms, Actions, optimistic

docs: useActionState
Action on a form
<form action={fn}> 19.0 — fn(formData) runs inside a transition; React resets an uncontrolled form on success. Also <button formAction>, <input formAction>
useActionState
const [state, action, isPending] = useActionState(fn, initialState, permalink?) 19.0 — fn(prevState, formData); state carries validation errors back. Renamed from the canary useFormState
useFormStatus
const { pending, data, method, action } = useFormStatus() 19.0 — from react-dom; must be in a component inside the <form>, not the one that renders it
useOptimistic
const [shown, addOptimistic] = useOptimistic(messages, (s, next) => [...s, next]) 19.0 — React reverts automatically when the action settles or throws
Controlled input
<input value={v} onChange={e => setV(e.target.value)} /> — value without onChange gives a read-only warning; value={undefined} silently switches the input to uncontrolled
Uncontrolled + FormData
<input name="email" defaultValue={u.email} /> then read formData.get('email') — with Actions this is usually the simpler design; no state per field
Error surfacing
Return { error } from the action and render state.error — a throw inside an action reaches the nearest error boundary instead
'use client';
function EditName({ current }) {
  const [state, action, isPending] = useActionState(async (prev, formData) => {
    const name = formData.get('name');
    if (!name) return { error: 'Name is required' };
    await updateName(name);                 // server function or fetch
    return { error: null, name };
  }, { error: null, name: current });

  return (
    <form action={action}>
      <input name="name" defaultValue={state.name} />
      <button disabled={isPending}>{isPending ? 'Saving…' : 'Save'}</button>
      {state.error && <p role="alert">{state.error}</p>}
    </form>
  );
}

// Submit button that knows about its own form, anywhere in the subtree.
function Submit() { const { pending } = useFormStatus(); return <button disabled={pending}>Send</button>; }

07Server Components

docs: React Server Components
Default is server
In an RSC framework every component is a Server Component until a file says otherwise — they never ship JS, may be async, and can read the database directly
'use client'
First line of a file — marks the boundary where the client bundle begins; everything it imports is bundled too. Push it as deep in the tree as possible
'use server'
First line of a file (or of a function body) — exports become Server Functions callable from the client. Not the marker for Server Components; it creates an HTTP endpoint, so validate and authorise inside every one
cache()
const getUser = cache(async (id) => db.user(id)) — dedupes per request in RSC; not for Client Components
cacheSignal()
const signal = cacheSignal(); await fetch(u, { signal }) 19.2 — aborts in-flight work once the cache lifetime ends (render aborted, response finished)
Passing data down
Props from a Server to a Client Component must be serialisable — plain data, JSX, promises and Server Functions are fine; class instances, Date methods and closures are not
Streaming a promise
Server: <Client rowsPromise={getRows()} />, client: use(rowsPromise) — the shell streams first, data fills in, no waterfall
Partial pre-rendering
const { prelude, postponed } = await prerender(<App />, { signal }), later resume() / resumeAndPrerender() 19.2 — cache the static shell at the CDN and resume the dynamic part per request
Taint APIs
taintObjectReference(msg, user) · taintUniqueValue(msg, obj, token) — hard-fail the render if a secret crosses to the client; cheap defence in depth around auth objects
// server.js — Server Component: async, zero client bytes, streams a promise down.
export default async function Page({ id }) {
  const user = await getUser(id);                 // cache()d, deduped per request
  return <Profile user={user} feedPromise={getFeed(id)} />;  // not awaited
}

// actions.js — every export is an HTTP endpoint. Authorise here, not in the caller.
'use server';
export async function deletePost(formData) {
  const session = await auth();
  if (!session?.canDelete) throw new Error('Forbidden');
  await db.post.delete({ id: String(formData.get('id')) });
}

Patch RSC before anything else on this card. CVE-2025-55182 ("React2Shell", CVSS 10.0, disclosed 2025-12-03) was an unauthenticated RCE in the RSC payload decoder of react-server-dom-webpack / -turbopack / -parcel 19.0–19.2.0, with public exploits within days; fixed in 19.0.1 / 19.1.2 / 19.2.1. The follow-ups found while auditing that patch — CVE-2025-55184 (DoS, 7.5) and CVE-2025-55183 (server-function source exposure, 5.3) — need 19.0.3 / 19.1.4 / 19.2.3 or later. Apps with no Server Functions endpoint were never exposed.

08react-dom & the document

docs: react-dom/client
Mount
createRoot(document.getElementById('root')).render(<App />) 18.0 — ReactDOM.render was removed in 19.0, not just deprecated
Hydrate
hydrateRoot(document, <App />) — ReactDOM.hydrate and unmountComponentAtNode also removed in 19.0
Portal
createPortal(<Modal />, document.body) — DOM moves, React tree and event bubbling do not
flushSync
flushSync(() => setOpen(true)); node.focus(); — forces a synchronous re-render; a performance escape hatch, not a pattern
Server render
renderToPipeableStream (Node) · renderToReadableStream (Web, and Node too 19.2) · renderToString for non-streaming — react-dom/server
Static render
prerender / prerenderToNodeStream, plus resumeAndPrerender 19.2 — react-dom/static, for SSG and partial pre-rendering
Document metadata
Render <title>, <meta>, <link rel="canonical"> anywhere 19.0 — React hoists them into <head>; react-helmet is now redundant
Stylesheets & scripts
<link rel="stylesheet" precedence="default" /> and <script async /> in the tree 19.0 — deduped, hoisted, and Suspense waits for the stylesheet before revealing
Resource hints
preload(href, { as: 'font' }) · preinit · prefetchDNS · preconnect · preloadModule / preinitModule 19.0 — from react-dom, callable in render or an event
import { createRoot } from 'react-dom/client';
import { preconnect, preload } from 'react-dom';

createRoot(document.getElementById('root'), {
  onUncaughtError: (err, info) => telemetry.report(err, info.componentStack),  // 19.0
}).render(<App />);

function Product({ p }) {
  preconnect('https://cdn.example.com');
  preload(p.heroSrc, { as: 'image', fetchPriority: 'high' });
  return (<>
    <title>{p.name} — Shop</title>               {/* hoisted to head (19.0) */}
    <meta name="description" content={p.blurb} />
    <img src={p.heroSrc} alt="" />
  </>);
}

10Idioms & gotchas

docs: Rules of React
Reset state on identity change
<Editor key={docId} /> — legacy: a useEffect that clears half a dozen useStates and flashes stale UI for one frame
Lift state, or push it down
Move state to the lowest common parent — or, when only one subtree cares, down into it — "state is too high" is the most common cause of a slow app
Composition beats context
Pass children so the expensive subtree is created by the parent — it does not re-render when the wrapper's state changes
Stale closure
A setInterval in an effect with [] deps sees the first render's state forever — fix with the updater form, or useEffectEvent 19.2
Index keys
key={i} on a reorderable/filterable list — checkbox state and focus attach to the wrong row; symptom is "the wrong item looks selected"
Objects in deps
useEffect(..., [{ id }]) re-runs every render — depend on primitives ([id]), never on freshly built objects
Controlled → uncontrolled
value={form.email} where email is undefined — React warns once and the input goes rogue; default to ''
Mutating state
items.push(x); setItems(items) does nothing — same reference. Use setItems([...items, x]), or Immer if the shape is deep
setState in render
Unconditional setX() during render is an infinite loop — set-state-in-render now catches it at lint time
Effect that should be a handler
Analytics/toasts fired from useEffect on a state change — fires twice in Strict Mode dev and on unrelated re-renders; put it in the event handler
Context value identity
<Ctx value={{ user, logout }}> rebuilds every render — memoise it, or let the compiler do it; otherwise every consumer re-renders
Suspense fallback thrash
An update that re-suspends replaces content with the fallback — wrap the update in startTransition to keep the old UI while the new one loads
Hydration mismatch
Non-deterministic render output on server vs client — gate with useSyncExternalStore's server snapshot or an effect; last resort suppressHydrationWarning on that node only
'use client' too high
A 'use client' at the layout root drags the whole tree into the bundle — the single biggest RSC bundle-size mistake
Unvalidated Server Function
Every 'use server' export is a public HTTP endpoint — authorise and validate inside it; the client-side check is decoration. See the 19.x CVEs in unit 07
Premature memo
memo/useMemo everywhere adds allocation and comparison cost — measure first; with React Compiler most hand-memoisation is dead weight

Governance, 2026-02-24. React, React Native and JSX are now owned by the React Foundation, hosted by the Linux Foundation, after an intent announced at React Conf on 2025-10-07. Eight platinum founding members (Amazon, Callstack, Expo, Huawei, Meta, Microsoft, Software Mansion, Vercel) fund a board; technical direction stays with a separate steering council of maintainers, so the release cadence and roadmap are unchanged. Nothing in your package.json changes — but "who owns React now?" is a fair interview question in 2026, and the answer is no longer "Meta".
