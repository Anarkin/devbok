Docker / Containerization

cheatsheet · Engine 29.8.0 · released 2026-09-03

This reflects Docker Engine 29.8.0, BuildKit 0.33.0 and Compose 5.5.1 — all released in the first week of September 2026 — plus Desktop 4.90.0 from 2026-09-07. The containerd image store is now the default storage backend on fresh Engine 29.x installs, BuildKit 0.33 finally lets Windows containers use RUN --mount=type=secret, and Docker Model Runner now ships disabled by default in current Desktop builds. Every row favours what a lead-to-principal engineer reaches for weekly, with the legacy pattern named alongside wherever it still turns up in real codebases.

01Core CLI & container lifecycle

docs: docker container
Run detached, self-cleaning, published
docker run -d --rm --name web -p 8080:80 nginx:1.27 — -d backgrounds it, --rm removes the container on exit, -p host:container publishes a port
Run interactively with a shell
docker run -it --rm alpine:3.20 sh
Exec into a running container
docker exec -it web sh — minimal images often have no bash, only sh
Follow logs
docker logs -f --tail 100 --timestamps web
List containers
docker ps running only · docker ps -a include stopped
Stop / kill / restart
docker stop web (SIGTERM, grace period) · docker kill web (SIGKILL) · docker restart web
Clean up
docker container prune stopped containers · docker image prune -a unused images · docker system prune -af --volumes everything unreferenced, volumes included — irreversible, see gotchas
Copy files in / out
docker cp web:/app/log.txt . · docker cp ./config.json web:/app/
Inspect one field
docker inspect -f '{{ .State.Health.Status }}' web — Go template syntax against the full JSON
Live resource stats
docker stats --no-stream
Processes inside a container
docker top web
Detach without stopping
docker attach web, then Ctrl-p Ctrl-q to leave it running
Runtime resource caps
docker run --memory=512m --memory-swap=512m --cpus=1.5 ...
Wait for exit code (CI, scripts)
docker wait web
Change policy on a live container
docker update --restart=unless-stopped web
Rename
docker rename web web-old

02Dockerfile: modern syntax & multi-stage

docs: Dockerfile reference
Pin the frontend (always line one)
# syntax=docker/dockerfile:1 — floats to the latest 1.x; without it, heredocs / mount flags / --link do not parse at all
Cache package installs across builds
RUN --mount=type=cache,target=/var/cache/apt apt-get update && apt-get install -y curl
Build secret, never in a layer
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc npm ci — pass it with docker build --secret id=npmrc,src=$HOME/.npmrc
Bind the build context instead of COPY
RUN --mount=type=bind,source=.,target=/src,ro go build -C /src -o /out/app ./...
Multi-line script, no && \ chain
heredoc — see example below syntax 1.4
Copy without ownership/mtime churn
COPY --link --chown=1000:1000 src/ /app/ syntax 1.4
Skip files beyond .dockerignore
COPY --exclude=**/*.md --exclude=**/*.test.* . .
Verified remote fetch
ADD --checksum=sha256:<digest> https://example.com/f.tar.gz /tmp/
Build one stage only (local dev)
docker build --target build -t app:dev .
Cross-compile for another platform
FROM --platform=$BUILDPLATFORM golang:1.24 AS build + ARG TARGETOS TARGETARCH
Healthcheck baked into the image
HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD curl -f http://localhost/health || exit 1
Drop root before CMD
USER 10001:10001
Exec form vs shell form
CMD ["nginx", "-g", "daemon off;"] (no shell, receives signals directly) vs CMD nginx -g 'daemon off;' (runs through /bin/sh -c, swallows signal 1)
# syntax=docker/dockerfile:1
FROM golang:1.24 AS build
WORKDIR /src
COPY go.* .
RUN --mount=type=cache,target=/root/.cache/go-build go mod download
COPY . .
RUN --mount=type=cache,target=/root/.cache/go-build go build -o /out/app .

# multi-line script without the classic "&& \" chain
RUN <<EOF
set -eux
go vet ./...
EOF

FROM gcr.io/distroless/base-debian12
COPY --from=build /out/app /app
USER nonroot:nonroot
ENTRYPOINT ["/app"]

03BuildKit, Buildx & Bake

docs: Docker Build
Build (BuildKit is the engine)
docker build -t app:1.0 . — BuildKit has been the default builder for plain docker build 23.0
Multi-platform image, one push
docker buildx build --platform linux/amd64,linux/arm64 -t user/app:1.0 --push .
Create / select a builder
docker buildx create --name multi --driver docker-container --use --bootstrap
Registry-backed layer cache (CI)
docker buildx build --cache-to type=registry,ref=user/app:cache,mode=max --cache-from type=registry,ref=user/app:cache .
Emit SBOM + provenance
docker buildx build --sbom=true --provenance=mode=max -t app:1.0 --push . — attestations default to OCI artifact descriptors BuildKit 0.32; payloads up to 80 MiB BuildKit 0.33
Every build target in one file
docker buildx bake web api — reads docker-bake.hcl (or .json) in the working directory
Reuse a Compose file as bake targets
docker buildx bake -f compose.yaml
Debug a failed step interactively
docker buildx debug --invoke sh build .
See why a layer missed cache
docker buildx build --progress=plain --no-cache-filter=<stage> .
Inspect the active builder
docker buildx inspect --bootstrap
Inspect a past build without rebuilding
docker buildx history ls / docker buildx history inspect <ref>
Windows build secrets
RUN --mount=type=secret,id=cred BuildKit 0.33 — first release to support this on Windows containers

docs: Docker Scout
Tag and push
docker tag app:1.0 registry.example.com/team/app:1.0 then docker push registry.example.com/team/app:1.0
Log in without a plaintext password
docker login registry.example.com -u ci --password-stdin
Inspect a remote manifest without pulling
docker buildx imagetools inspect user/app:1.0
See why an image is big
docker history --no-trunc app:1.0
CVE scan + fix suggestion
docker scout cves app:1.0 · docker scout recommendations app:1.0
Did this build regress security?
docker scout compare app:1.0 --to=app:0.9
Read the SBOM baked into an image
docker buildx imagetools inspect app:1.0 --format '{{ json .SBOM }}'
Move an image without a registry
docker save app:1.0 -o app.tar / docker load -i app.tar
Sign an image

Remove dangling/untagged layers

List local images
docker images

05Networking

docs: networking overview
List / inspect
docker network ls / docker network inspect bridge
Isolated network per project
docker network create --driver bridge appnet
Attach a running container to another network
docker network connect appnet web
Publish vs expose
-p 8080:80 opens a host port; EXPOSE 80 in a Dockerfile is documentation only and publishes nothing
Bind to one interface, not every one
docker run -p 127.0.0.1:8080:80 ... — on a shared host, the default 0.0.0.0 publish is often the actual security bug
Name-based DNS between containers
only on a user-defined network (appnet above) — the default bridge network has none
Share another container's network stack
docker run --network container:web ...
Host networking (Linux only)
docker run --network host ...
Debug DNS/connectivity from inside
docker run --rm --network appnet nicolaka/netshoot dig web
IPv6
docker network create --ipv6 --subnet fd00:dead:beef::/64 appnet6 — dual-stack default bridge network available 28.0

06Volumes & storage drivers

docs: storage overview
Named volume (Docker-managed, portable)
docker run -v app-data:/var/lib/app ...
Bind mount (host path, dev inner loop)
docker run -v "$(pwd)/src:/app/src" ...
Explicit long syntax when it's not obvious
--mount type=volume,source=app-data,target=/var/lib/app
Read-only mount
-v ./config.json:/app/config.json:ro
tmpfs for scratch that must never touch disk
docker run --tmpfs /run:rw,size=64m ...
List / inspect / remove
docker volume ls / docker volume inspect app-data / docker volume prune
Back up a volume
docker run --rm -v app-data:/data -v "$(pwd)":/backup alpine tar czf /backup/data.tgz -C /data .
Which storage backend is active
docker info -f '{{ .DriverStatus }}'
Opt into the containerd image store
daemon.json below, then sudo systemctl restart docker default on fresh installs since Engine 29.0
Switching snapshotters
hides, but does not delete, images/containers created under the previous one — check with docker info before assuming data loss
{
  "features": { "containerd-snapshotter": true }
}

07Docker Compose

docs: Compose
Up, rebuild if needed, detached
docker compose up -d --build
Tear down, drop volumes too
docker compose down -v
Follow one service's logs
docker compose logs -f api
One-off command in a fresh container
docker compose run --rm api pytest
Shell into a running service
docker compose exec api sh
Live sync + rebuild on change
docker compose watch 2.22
Scale a service
docker compose up -d --scale worker=3
Start only part of the stack
docker compose --profile debug up -d
Validate & print the merged config
docker compose config
Wait for "ready", not just "started"
depends_on: db: condition: service_healthy — needs a real healthcheck: on db, see example below
Pre-start lifecycle hook
pre_start: service hook 5.3 — replaces hand-rolled wait scripts run before the app container starts
Layer config per environment
docker compose -f compose.yaml -f compose.prod.yaml up -d
The version: key
obsolete since the Compose Specification — omit it, the schema is inferred from the file's shape
Pull policy with a refresh window
pull_policy: daily 5.5 — re-pulls at most once a day instead of on every up
services:
  db:
    image: postgres:17
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
      timeout: 3s
      retries: 10
  api:
    build: .
    depends_on:
      db:
        condition: service_healthy
    develop:
      watch:
        - action: sync
          path: ./src
          target: /app/src

08Security & resource limits

docs: security
Never run as root
USER 10001:10001 near the end of the Dockerfile
Drop all capabilities, add back what's needed
docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE ...
Read-only root filesystem
docker run --read-only --tmpfs /tmp ...
Block privilege escalation
docker run --security-opt=no-new-privileges ...
Custom seccomp / AppArmor profile
--security-opt seccomp=profile.json / --security-opt apparmor=profile-name — AppArmor profile customization 29.8
Resource caps
--cpus=1.5 --memory=512m --pids-limit=256
Per-device block I/O limits
--device-read-bps /dev/sda:10mb 29.6 — per-device blkio settings added to the API
Rootless daemon (no root process at all)
dockerd-rootless-setuptool.sh install
Per-container umask
docker run --umask=0027 ... 29.8
Survive a reboot, not a manual stop
--restart unless-stopped
Never mount the host socket into an untrusted container
avoid -v /var/run/docker.sock:/var/run/docker.sock — it is root-equivalent access to the host, not a sandbox boundary

09Gotchas & pitfalls

docs: build best practices
  • docker run without -d blocks the shell and dies with your terminal — use -d, not &, if it should outlive the session.
  • EXPOSE publishes nothing. Only -p/--publish opens a host port; EXPOSE is metadata for humans and tools like Compose.
  • The default bridge network has no container-name DNS. Multi-container apps need a user-defined network — Compose creates one for you automatically.
  • latest is not "the latest stable." It's whatever the maintainer last pushed under that tag; pin a real version, and a digest for anything you ship.
  • docker system prune -af --volumes deletes unreferenced volumes too, irreversibly. Read the confirmation prompt before scripting past it.
  • A bind mount shadows whatever the image already had at that path. "Missing files in the container" is as often a mount hiding the build's own output as it is a build bug.
  • Build cache invalidates from the first changed instruction onward. Put the steps that rarely change (package installs, go mod download) before COPY . ., never after.
  • depends_on alone only waits for "container started," not "app ready." Pair it with condition: service_healthy and a real HEALTHCHECK, or the first request still races the database.
  • Mounting /var/run/docker.sock into a container hands it root on the host. It is not a sandbox; it's a different name for "give this process root."
  • --restart=always on a crash-looping container is an infinite restart loop that burns CPU and fills the log driver — use unless-stopped and fix the healthcheck instead.
  • COPY --from=<image> re-resolves that tag whenever BuildKit can't satisfy it from cache — an unpinned tag drifts silently; pin the digest for anything reproducible.
  • Line endings and permission bits don't always survive a bind-mount round-trip identically between Windows/WSL2 and Linux — CRLF creeping into a shell script is a classic "works on my machine."
