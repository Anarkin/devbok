Redis (for .NET developers)

cheatsheet · 8.10.1 · released 2026-08-17

Reflects Redis 8.10.1, released 2026-08-17 as a same-day security patch across every active branch (8.2 through 8.10). Redis has been tri-licensed under RSALv2, SSPLv1 and AGPLv3 since 8.0.0 (2025-05-02); Valkey, the Linux Foundation's BSD-licensed fork, is the drop-in alternative wherever that licence is a blocker. .NET examples assume StackExchange.Redis 3.1.31, which negotiates RESP3 by default and enforces AllowAdmin client-side.

01Connect & clients (.NET)

One ConnectionMultiplexer per process, shared behind DI — the client, not Redis, is usually the bottleneck when someone reaches for a second one.

Install
dotnet add package StackExchange.Redis (3.1.31)
DI (ASP.NET Core)
services.AddSingleton<IConnectionMultiplexer>(_ => ConnectionMultiplexer.Connect(cs));
.NET Aspire
builder.AddRedisClient("cache"); — Aspire.StackExchange.Redis 13.5.3, wires health checks + telemetry
Two-tier app cache
services.AddHybridCache().AddStackExchangeRedisCache(o => o.Configuration = cs); — Microsoft.Extensions.Caching.Hybrid 10.9.0, in-proc L1 + Redis L2, stampede protection
Get a database
IDatabase db = mux.GetDatabase();
Protocol
RESP3 negotiated by default since StackExchange.Redis 3.0.0 — was RESP2-only in 2.x
Admin guard
ConfigurationOptions.AllowAdmin = true — enforced client-side since 3.0.0: FLUSHALL/FLUSHDB/CONFIG now throw locally, not just server-side, without it
I/O layer (3.0.0)
direct-buffer reader replaced Pipelines.Sockets.Unofficial + the arena parser — ~2.2× the LRANGE throughput in the release benchmark, same public API as 2.x
Search/JSON/TS client
NRedisStack 1.7.4 — db.JSON() · db.FT() · db.TS()
Connection string
host:port,password=...,ssl=true,abortConnect=false,connectTimeout=5000
Transient failure
RedisConnectionException / RedisTimeoutException — retry with backoff (Polly), never a tight loop
CLI ping
redis-cli -h host -p 6380 --tls -a pass PING
var mux = await ConnectionMultiplexer.ConnectAsync(
    "cache.internal:6380,ssl=true,password=REDACTED,abortConnect=false");
IDatabase db = mux.GetDatabase();
await db.StringSetAsync("session:42", json, TimeSpan.FromMinutes(30));
var val = await db.StringGetAsync("session:42");

03Expiry, eviction & memory

Guarded expire (modern)
EXPIRE k 60 NX / XX / GT / LT — 7.0.0
Unconditional (legacy)
EXPIRE k 60 — overwrites any existing TTL blindly
Field TTL
HTTL k FIELDS 1 f · HPERSIST k FIELDS 1 f — 7.4.0
Inspect TTL
TTL k (seconds) · PTTL k (ms)
Eviction policy (config)
maxmemory-policy noeviction (default) | allkeys-lru | volatile-lru | allkeys-lfu | volatile-lfu
Cheap recency (new)
allkeys-lrm | volatile-lrm — 8.6.0, timestamp updates on writes only, not on every read
Memory cap
maxmemory 2gb
Inspect memory
MEMORY USAGE k · MEMORY DOCTOR · MEMORY STATS
Active defrag
activedefrag yes — jemalloc-dependent
Hot key detection (new)
HOTKEYS START · HOTKEYS GET · HOTKEYS STOP — 8.6.0
Hot key detection (legacy)
redis-cli --hotkeys — blocking full-keyspace scan + sampling

Default is not a safety net. maxmemory with noeviction (the default policy) does not evict anything once the cap is hit — it starts rejecting writes with OOM command not allowed. Pick a policy deliberately for a cache; don't inherit the default meant for a primary store.

04Transactions, scripting & pipelining

Pipeline (no atomicity)
batch commands, one round trip; SE.Redis: IBatch or CommandFlags.FireAndForget
Optimistic transaction
WATCH k / MULTI … EXEC — SE.Redis: ITransaction
Server-side function (modern)
FUNCTION LOAD "#!lua name=lib..." — 7.0.0, versioned, listed via FUNCTION LIST
Ad-hoc script (legacy)
EVAL "return redis.call('get', KEYS[1])" 1 k — no library, no version, cached by SHA (EVALSHA)
Wait for AOF fsync
WAITAOF numlocal numreplicas timeout — 7.2.0
Wait for replication
WAIT numreplicas timeout
Lock (pattern)
SET lock:res token NX PX 30000, unlock via a script that compares the token before DEL

A single-instance lock is not a distributed lock. SET NX PX plus a compare-and-delete unlock is the classic pattern — Redis's own documentation calls it discouraged for correctness-critical mutual exclusion. Use Redlock (RedLock.net) across independent instances when a failover must not let two clients hold the "same" lock.

#!lua name=orders
redis.register_function('bump_stock', function(keys, args)
  local n = tonumber(redis.call('HINCRBY', keys[1], 'stock', -tonumber(args[1])))
  if n < 0 then return redis.error_reply('oversell') end
  return n
end)
-- FUNCTION LOAD "#!lua name=orders\n..."
-- FCALL bump_stock 1 sku:42 3

05Pub/Sub & Streams

Pub/Sub is fire-and-forget with no backlog; a Stream is a durable, replayable log with per-consumer acknowledgement — pick by whether a missed message is acceptable.

Fire-and-forget
PUBLISH ch msg · SUBSCRIBE ch
Cluster-aware (modern)
SPUBLISH ch msg · SSUBSCRIBE ch — 7.0.0, shard-local delivery, scales with the cluster
Cluster-unaware (legacy in Cluster)
PUBLISH broadcasts to every node regardless of shard
Durable log
XADD k * f v + XREADGROUP consumer groups — replay, per-consumer ack, backlog; Pub/Sub delivers to nobody if nobody is listening
Consumer failover
XAUTOCLAIM k g consumer 0 0 — claims idle PEL entries from a dead consumer
Trim (cheap)
XADD k MAXLEN ~ 10000 * f v — approximate, near O(1)
Trim (exact)
XTRIM k MAXLEN 10000 — exact, more work
Read a range
XRANGE k - +
Pending entries
XPENDING k g

08Search, JSON, vector & probabilistic

Query Engine, JSON, Time Series, probabilistic structures and Vector Sets are all core commands since 8.0.0 — no separate module build or licence to add.

Document store
JSON.SET k $ '{"a":1}' · JSON.GET k $.a — core since 8.0.0, was the standalone RedisJSON module before
Secondary index
FT.CREATE idx ON JSON PREFIX 1 doc: SCHEMA $.a AS a NUMERIC $.vec AS vec VECTOR HNSW 6 TYPE FLOAT32 DIM 128 DISTANCE_METRIC COSINE
Hybrid filter + vector
FT.SEARCH idx "@a:[1 10] =>[KNN 5 @vec $B]" PARAMS 2 B ... DIALECT 2 — filter and ANN in one query
Pure similarity (new)
VADD k VALUES 3 0.1 0.2 0.3 elem · VSIM k VALUES 3 ... WITHSCORES — 8.0.0, HNSW-graph-backed, no index to build
Remove an element
VREM k elem

09Security: ACL & TLS

Least privilege
ACL SETUSER svc on >pass ~cache:* +get +set -@admin
Inspect
ACL WHOAMI · ACL LIST · ACL LOG
TLS in .NET
ssl=true in the connection string; a CertificateValidation callback for pinning
Disable dangerous cmds (modern)
ACL -@dangerous per user/role
Disable dangerous cmds (legacy)
rename-command FLUSHALL "" in redis.conf — breaks cluster/Sentinel introspection that expects the real name

CVE-2026-62356 — fixed in 8.10.1 (2026-08-17). A NUL-byte-truncated Common Name in a TLS client certificate could let a client authenticate as a different, more-privileged ACL user. The same release also fixed a heap out-of-bounds write loading a CMSketch from RDB, a TopK out-of-bounds cleanup bug, and three Vector Sets memory-safety bugs (RDB validation, a VREM/VSIM use-after-free race, and a negative hnsw_search() return read as a huge unsigned count) — patched the same day across every active branch: 8.2.9, 8.4.6, 8.6.6, 8.8.2, 8.10.1. Pin at least the matching patch on your branch before trusting cert-based ACL mapping or loading untrusted dumps that touch CMSketch/TopK/Vector Set keys.

10Gotchas & pitfalls

  • KEYS * on production blocks the single event loop — use SCAN (cursor-based), never KEYS, outside a laptop.
  • FLUSHALL/FLUSHDB without AllowAdmin = true throws client-side in StackExchange.Redis 3.x before it ever reaches the server.
  • A cross-slot multi-key command in Cluster mode throws CROSSSLOT unless every key shares a {tag}.
  • A big Hash/Set/ZSet (the "big key" problem) blocks replication, defrag and RDB save — watch MEMORY USAGE, split hot keys.
  • An EXPIRE race from read-then-write TTL logic — use the NX/XX/GT/LT guards (7.0.0) instead.
  • Lua/Functions must stay deterministic across replicas — use redis.call('TIME'), never wall-clock or ambient randomness.
  • SET NX as a "distributed lock" is not safe across a failover — Redis's own docs recommend Redlock, not a single instance.
  • Pipelining batches round trips; it does not make commands atomic — use MULTI/EXEC or a Function when atomicity matters.
  • SE.Redis 2.x → 3.x keeps the same public API, but RESP3 is now the default and AllowAdmin is now enforced locally — re-test admin-flagged commands and anything that assumed RESP2 wire behaviour.
  • maxmemory with the default noeviction policy does not evict — it starts rejecting writes with OOM command not allowed once the cap is hit.
  • A dangling PEL reference from legacy XDEL can make consumer-group accounting look wrong until XACKDEL DELREF or XAUTOCLAIM cleans it up.
  • Loading an untrusted RDB/dump on a version older than 8.10.1 risks the CMSketch/TopK/Vector Set memory-safety bugs fixed that release — treat old dumps as untrusted input until you've patched.
