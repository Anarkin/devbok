JavaScript & TypeScript

cheatsheet · TypeScript 7.0 · ES2026 · Node.js 26.8.1 · released 2026-07-08

The language pair on one card: TypeScript's type syntax, generics, narrowing and the tsconfig flags that actually change behaviour, next to the JavaScript standard library, module semantics and async model a working engineer types weekly. Read as TypeScript 7.0 (the Go-native compiler, GA 2026-07-08) targeting ES2026 (ratified 2026-06-30) on Node.js 26 — browser-only or Deno/Bun-only differences are called out where they bite, but Node is the assumed runtime. Verified 2026-09-08: TS 7.0 turned TS 6.0's deprecations into hard errors and still ships no public compiler API (due in 7.1, autumn 2026), Node 26 made TypeScript type stripping stable and Temporal unflagged, and strict is now on by default.

01Types & annotations

docs: TS handbook — everyday types
Primitives
string number boolean bigint symbol null undefined — lower-case always; String/Number are the wrapper objects and never what you want
Top types
unknown = safe top (must narrow before use) · any = opt out of checking · object = any non-primitive — reach for unknown at every boundary
Bottom types
never = unreachable / empty union · void = return value ignored — a void-returning callback may still return a value; never may not
Literal & union
type Mode = "r" | "w" | "rw" · discriminated union: every member shares a literal tag field
interface vs type
interfaces merge across declarations and give better errors on object shapes; type does unions, tuples, mapped and conditional types — interface for public object contracts, type for everything else
Object modifiers
readonly x: T, y?: T, index signature [k: string]: T, Record<K, V>
Tuples
[string, number], named [name: string, age: number], variadic [first: T, ...rest: U[]], readonly [1, 2]
as const
freezes literals and infers the narrowest type: const R = ["GET","POST"] as const then type M = typeof R[number]
satisfies TS 4.9
check against a type without widening the inferred one — the correct replacement for const x: T = … on config objects
Function types
(a: string, b?: number) => void · overloads via multiple signatures · this parameter as the first parameter
Enums
prefer as const objects + a union type; enum emits runtime code and is banned by erasableSyntaxOnly — const enum breaks under isolatedModules
Declaration files
.d.ts ambient types · declare module "x" · declare global { … } · export {} makes a file a module
// satisfies: validated, but each value keeps its literal type
const routes = {
  home: { path: "/", auth: false },
  admin: { path: "/admin", auth: true },
} satisfies Record<string, { path: `/${string}`; auth: boolean }>;
routes.admin.path; // "/admin", not string

// as const object instead of enum — zero runtime cost, erasable
const Level = { Debug: 10, Info: 20, Error: 40 } as const;
type Level = (typeof Level)[keyof typeof Level]; // 10 | 20 | 40

Structural, not nominal. Two types with the same shape are interchangeable. Brand when identity matters: type UserId = string & { readonly __brand: unique symbol }.

02Generics & type operators

docs: TS handbook — generics
Constraints & defaults
function f<T extends object = {}>(x: T): T — constrain to what you actually use, not to any
const type params TS 5.0
function pick<const T extends readonly string[]>(keys: T) — infers literals without the caller writing as const
NoInfer<T> TS 5.4
excludes a position from inference: function pick<T>(all: T[], one: NoInfer<T>)
keyof / typeof
keyof T = union of keys · typeof value = the type of a runtime binding · indexed access T["k"], T[number]
Mapped types
{ [K in keyof T]: … } with +/-readonly, +/-?, and key remapping as `get${Capitalize<K & string>}`
Conditional types
T extends U ? A : B, infer to capture, distributive over naked unions — wrap in [T] to stop distribution
Template literals
type Ev = `on${Capitalize<string & keyof T>}` · built-ins Uppercase Lowercase Capitalize Uncapitalize
Utility types
Partial Required Readonly Pick Omit Record Exclude Extract NonNullable ReturnType Parameters Awaited InstanceType
Variance annotations TS 4.7
interface Box<in out T> — documents and speeds up assignability checks on large generic types
declare const tricks
type-level tests: type Expect<T extends true> = T plus Equals<A, B> keeps public types from silently drifting
// infer + template literal: parse route params out of a path string
type Params<S extends string> =
  S extends `${string}:${infer P}/${infer Rest}` ? P | Params<`/${Rest}`> :
  S extends `${string}:${infer P}` ? P : never;
type P = Params<"/org/:orgId/user/:userId">; // "orgId" | "userId"

// exhaustiveness: the compiler proves every case is handled
function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.r ** 2;
    case "rect":   return s.w * s.h;
    default: { const _never: never = s; return _never; }
  }
}

Depth costs money. Deep conditional recursion is the usual cause of a slow tsc. Measure with tsc --diagnostics --generateTrace ./trace before optimising types by feel.

03Narrowing & guards

docs: TS handbook — narrowing
Built-in narrowers
typeof · instanceof · in · Array.isArray · truthiness · equality against a literal or null
Discriminant switch
switch (x.kind) on a literal tag — the cheapest exhaustive dispatch; close it with a never default
Type predicate
function isUser(x: unknown): x is User — you are asserting, the compiler is not checking; keep the body trivial
Inferred predicates TS 5.5
xs.filter(x => x !== null) now narrows on its own, without an explicit x is T signature
Assertion functions
function assert(c: unknown): asserts c · function assertUser(x: unknown): asserts x is User — must be a declared function, not an arrow in a let
in on untagged unions
if ("error" in res) narrows union members that share no discriminant field
Non-null assertion
x!.y — a lie to the compiler with zero runtime effect; prefer x ?? raise() or an assertion function
as casts
only move along the subtype chain; as unknown as T is the escape hatch that eventually bites
Optional chaining
a?.b, a?.[i], a?.() short-circuit to undefined ES2020 — a?.b.c guards the whole chain, not just b
Nullish coalescing
a ?? d falls back only on null/undefined; a || d also swallows 0, empty string, false · a ??= d ES2021
Closure narrowing TS 5.4
narrowing survives into a closure created after the last assignment — the old copy-into-a-local dance is mostly gone
Runtime validation
types vanish at runtime: validate untrusted JSON with a schema library (Zod / Valibot / ArkType) or hand-written predicates, then trust the inferred type
// unknown at the boundary, narrowed once, typed everywhere after
async function loadUser(id: string): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`, { cause: res });
  const data: unknown = await res.json();
  if (!isUser(data)) throw new TypeError("bad user payload");
  return data; // User
}

function isUser(x: unknown): x is User {
  return typeof x === "object" && x !== null && "id" in x && typeof x.id === "string";
}

04Modules & resolution

docs: Node.js — packages & exports
ESM basics
import x, { y as z } from "m" · export default · export * as ns from "m" · import.meta.url · top-level await ES2022
Dynamic import
const m = await import("./heavy.js") — returns a namespace object; the only way to load conditionally
import defer TS 5.9
import defer * as ns from "./heavy.js" — the module evaluates on first property access; Stage 3, aimed at deep graphs with costly top-level side effects
Import attributes ES2025
import cfg from "./c.json" with { type: "json" } · dynamic form import(u, { with: { type: "json" } })
Type-only imports
import type { T } from "m" · import { type T, value } from "m" · export type { T } — mandatory under verbatimModuleSyntax
Package entry points
"exports" map with "types" first, then "import"/"require"/"default" — main/module/browser are legacy fallbacks
Subpath imports
"imports": { "#/*": "./src/*" } in package.json — aliases the runtime honours; TS 6.0 accepts the bare #/ prefix
CJS and ESM
require(esm) on by default Node 22.12 / 24 · createRequire(import.meta.url) the other way · __dirname becomes import.meta.dirname Node 20.11
Extension rules
"type": "module" makes .js ESM; .mjs/.cjs force it per file; TS mirrors with .mts/.cts emitting .mjs/.cjs
Relative specifiers
ESM requires the extension. Under nodenext you write the output extension: import "./util.js" inside util.ts
Resolution modes
nodenext (libraries, Node apps) · bundler (Vite/webpack apps, extensionless allowed) — node, node10, classic are gone in TS 7.0
Circular imports
ESM hoists bindings, so cycles appear to work until a top-level read hits the TDZ — symptom is Cannot access X before initialization
{
  "name": "@acme/core",
  "type": "module",
  "exports": {
    ".":        { "types": "./dist/index.d.ts", "import": "./dist/index.js", "require": "./dist/index.cjs" },
    "./client": { "types": "./dist/client.d.ts", "default": "./dist/client.js" },
    "./package.json": "./package.json"
  },
  "imports": { "#/*": "./dist/*" },
  "engines": { "node": ">=24" }
}

Dual-package hazard. Ship one format when you can. If a package resolves as both CJS and ESM, two copies of its module state live in one process — instanceof checks and singletons quietly stop working.

05Async & iteration

docs: MDN — using promises
Combinators
all (fails fast) · allSettled (never rejects) · race (first settle) · any (first fulfil, else AggregateError)
Promise.withResolvers() ES2024
const { promise, resolve, reject } = Promise.withResolvers<T>() — retires the captured-resolver deferred pattern
Promise.try() ES2025
runs a sync-or-async function and routes a synchronous throw into the promise chain instead of the call stack
Cancellation
AbortController plus { signal }; AbortSignal.timeout(ms), AbortSignal.any([a, b]) — promises themselves are not cancellable
Event loop order
sync → microtasks (await, .then, queueMicrotask) → macrotasks (timers, I/O). A microtask loop starves rendering and I/O
Concurrency limit
no built-in pool — chunk the work or use p-limit; an unbounded Promise.all(items.map(fetch)) is a self-inflicted DoS
Async iteration
for await (const x of stream) · async function* · Symbol.asyncIterator · await using for async cleanup
Iterator helpers ES2025
it.map .filter .take .drop .flatMap .reduce .toArray .some .every .find — lazy, on any iterator
Iterator.concat() ES2026
chains iterators without materialising arrays; Iterator.from(x) lifts a plain iterable into the helper protocol
Array.fromAsync() ES2026
await Array.fromAsync(asyncGen) — the async twin of Array.from, sequential by design
Node concurrency
worker_threads for CPU work · AsyncLocalStorage for request context · node:stream/promises pipeline() for backpressure
Unhandled rejection
terminates the process by default since Node 15 — always await or .catch() a floating promise
// bounded concurrency + per-attempt timeout + cooperative cancellation
async function mapLimit<T, R>(xs: T[], n: number, fn: (x: T) => Promise<R>): Promise<R[]> {
  const out: R[] = new Array(xs.length);
  let i = 0;
  const workers = Array.from({ length: Math.min(n, xs.length) }, async () => {
    while (i < xs.length) { const k = i++; out[k] = await fn(xs[k]!); }
  });
  await Promise.all(workers);
  return out;
}

const signal = AbortSignal.any([AbortSignal.timeout(2_000), userAbort.signal]);
const rows = await mapLimit(ids, 8, (id) => fetch(`/api/${id}`, { signal }).then((r) => r.json()));

07Classes, decorators, using

docs: TS handbook — classes
Fields
class fields ES2022, #private (hard private, enforced at runtime), static fields and static { } initialiser blocks
private vs #
TS private is compile-time only and visible from JS; #name is a real private slot and throws on foreign access
Parameter properties
constructor(private readonly repo: Repo) {} — concise, but emits code, so it is illegal under erasableSyntaxOnly and unusable with Node's type stripping
Accessors
get/set, accessor x = 1 (auto-accessor, ES decorators) · override keyword with noImplicitOverride
Abstract
abstract class, abstract method(): T · implements I checks the shape but does not import members
Standard decorators TS 5.0
ES-proposal decorators, no flag needed: (value, context) => … with context.kind, context.name, context.addInitializer()
Legacy decorators
experimentalDecorators + emitDecoratorMetadata + reflect-metadata — still what Angular, NestJS and TypeORM require; the two flavours cannot be mixed in one file
Decorator metadata TS 5.2
context.metadata and Symbol.metadata — the standard replacement for emitDecoratorMetadata
using TS 5.2
using f = open(path) calls [Symbol.dispose]() at scope exit; await using calls [Symbol.asyncDispose](). Stage 4; V8 ships it, Node exposes the symbols since 24
DisposableStack
aggregate cleanup: stack.use(res), stack.defer(fn), stack.move() to hand ownership on; async twin AsyncDisposableStack
Prototypes
Object.create, Object.getPrototypeOf, Object.setPrototypeOf (deoptimises — avoid on hot paths) · Object.hasOwn(o, k) ES2022
this binding
arrow functions capture lexically; methods do not. Class fields holding arrows bind per instance at the cost of one closure each
// deterministic cleanup, no try/finally pyramid
class Conn implements Disposable {
  #handle = openHandle();
  [Symbol.dispose]() { this.#handle.close(); }
}

function query(sql: string) {
  using conn = new Conn();          // disposed on every exit path, throws included
  return conn.run(sql);
}

// standard decorator: no experimentalDecorators, no reflect-metadata
function logged<T, A extends unknown[], R>(
  fn: (this: T, ...a: A) => R,
  ctx: ClassMethodDecoratorContext<T>,
) {
  return function (this: T, ...a: A): R {
    console.time(String(ctx.name));
    try { return fn.call(this, ...a); } finally { console.timeEnd(String(ctx.name)); }
  };
}

10Idioms & gotchas

docs: MDN — JavaScript reference

Idioms worth keeping

Result over throw
a { ok: true; value: T } | { ok: false; error: E } union makes failure a checked case; throw for programmer errors, return for expected ones
Parse, don't validate
turn unknown into a domain type once at the edge; everything downstream is typed and needs no defensive checks
Builder-free config
{ …defaults, …overrides } satisfies Config beats an options class; the literal types survive
Branded ids
type OrderId = string & { readonly brand: unique symbol } stops a userId being passed where an orderId belongs
Exhaustive dispatch
discriminated union + switch + never default: adding a variant becomes a compile error at every handler
Narrow module surface
one index.ts barrel per package boundary, none inside — internal barrels create cycles and defeat tree shaking
Structural logging context
AsyncLocalStorage for correlation ids beats threading a ctx parameter through every signature
Errors carry causes
throw new Error("checkout failed", { cause: err }) — preserves the chain instead of stringifying it

Gotchas, one line each

  • typeof null === "object" — a 1995 bug that can never be fixed; test with x === null.
  • [1, 10, 2].sort() gives [1, 10, 2]: the default comparator is lexicographic. Always pass one.
  • 0.1 + 0.2 !== 0.3. Use integer minor units for money, or Math.sumPrecise for float sums.
  • NaN !== NaN; use Number.isNaN, never the global isNaN (which coerces).
  • parseInt("08") is fine today but parseInt(x) without a radix is still a review smell — use Number(x).
  • Spread and Object.assign are shallow; nested objects stay shared. Use structuredClone for a real copy.
  • readonly and Readonly<T> are compile-time only — nothing stops JS callers mutating. Object.freeze is the runtime version.
  • as never checks anything at runtime; a wrong cast surfaces thousands of lines later as undefined is not a function.
  • any propagates silently through every expression it touches; unknown is almost always the right choice.
  • Excess property checks apply only to fresh object literals — assign through a variable and typos slip past.
  • JSON.stringify drops undefined, functions and symbols, and throws on BigInt and cycles.
  • Date months are 0-indexed and new Date("2026-09-08") parses as UTC while "2026/09/08" parses as local. Prefer Temporal.
  • for…in walks inherited enumerable keys; for…of walks values. Use Object.keys/entries for own keys.
  • await inside a for loop serialises; that is sometimes what you want and usually not.
  • Array.prototype.forEach ignores async callbacks — the loop finishes before any of them do.
  • A catch binding is unknown under useUnknownInCatchVariables (part of strict) — narrow with Error.isError.
  • enum members are bidirectionally mapped at runtime, so Level[40] yields "Error", and the whole thing survives tree shaking.
  • Node type stripping does not transform: enum, namespace, parameter properties and legacy decorators need a real compiler.
  • Optional chaining on a function call, obj.method?.(), still evaluates the arguments — no short-circuit there.
  • Two module instances (CJS + ESM copies of the same package) break instanceof, singletons and module-level caches.
  • Object.keys order is integer-like keys ascending first, then insertion order — do not rely on it for anything semantic.
  • Class fields initialise after super(), so a base-class constructor cannot see a derived field.
